# 指令帳本（instruction ledger）

review 第 2.7 步讀這份。目的：讓 CLAUDE.md 與制度檔的瘦身有依據——每條指令都有一個裁決、一份證據、一句刪掉會怎樣。只產提案，不改檔。

## 範圍

| 收 | 不收 |
|---|---|
| workspace 根 `CLAUDE.md`、`CLAUDE.local.md`（有的話） | 變更紀錄檔（`CHANGELOG.md`、`*.changelog.md`） |
| `.claude/rules/*.md` | 產生物：`.claude/harness/flow.md`、`install-report.md`、`reviews/` |
| `.claude/harness/*.md`（README 與 02～05、01／06 有的話） | 知識筆記（詞彙表、FLOWS.md、PROJECT.md）：記事實，不是指令 |
| `.claude/agents/*.md` | memory：淘汰走學習迴路的淘汰候選（報告第 10 段） |
| `.claude/skills/*/SKILL.md`（專案自己的 skill） | plugin 的檔、全域 CLAUDE.md（不屬於這個專案；重複時只當證據引用） |

逐檔範圍：上一份帳本（`reviews/` 底下最新的 `*-ledger.md`）之後有異動的檔，加上 §5 清單判「長胖」的檔；沒有上一份帳本就全收。使用者要全面重做時全收。

## 粒度

一列＝一條指令：一個條列項、一個編號項、表格的一列，或一句能單獨照做的規定。解釋理由的段落併進它支撐的那條，不另立一列。整節裁決相同時（例：整節搬到同一個檔）可以一列代表整節，在指令欄寫「§X 整節，N 條」。位置寫 `檔名:起始行`。

## 五種裁決

| 裁決 | 何時 | 這一列必須寫出 |
|---|---|---|
| retain 留 | 有在起作用的證據，或它擋的是有紀錄的事故、沒有別的東西擋 | 證據 |
| rewrite 改寫 | 規則該留，但寫法有問題：過長、跟別條重複要合併、前提變了、措辭讓模型讀錯 | 新文字全文（照抄就能貼） |
| relocate 搬 | 規則該留，但只在特定情境才用得到，常駐在這裡佔每次的 context | 目的地檔:節、讀取路徑（下面四種之一）、誰在什麼時候會讀到 |
| automate 改成自動檢查 | 違反時從工具呼叫的樣子認得出來（指令字串、寫入路徑、派工欄位） | 哪支 hook（既有的寫規則 id，新的寫建議檔名）、原文留什麼（通常一行或不留） |
| delete 刪 | 模型不用提醒也會做；跟別處重複（寫出另一處的檔:行）；前提已不存在；從沒起作用也沒有事故來源 | 刪的理由 |

**搬到沒人讀的檔等於刪。** relocate 的目的地必須有讀取路徑，四種之一：

1. CLAUDE.md 路由表有一列指到它，且那一列的觸發情境跟這條規則用得到的情境一致
2. 有 hook 在對應事件把它注入（寫出 hook 檔名與事件）
3. 列在某個 skill 或 04 派工範本的【開工前必讀】清單裡（寫出哪一份、哪一行）
4. `.claude/rules/` 底下帶 `paths:` 的規則檔，碰到符合的檔時自動載入（寫出 glob，並附這個 glob 在 repo 裡實際比對到的檔數——0 個等於沒有讀取路徑）

目的地現在還沒有讀取路徑時，提案要連「補上讀取路徑」一起寫（例：同時在路由表加一列），兩件一起核可、一起套用。寫不出讀取路徑就改判 delete，照 delete 評風險。目的地的用量（下一節）是 0 時，讀取路徑存在也要在證據欄註明「目的地從沒被讀過」。

## 證據：先用既有資料，不另做統計

依序找，找到能支撐裁決的就停：

| 來源 | 在收集結果的哪裡 | 能證明什麼 |
|---|---|---|
| 制度檔被讀的次數 | `J.usage.top` 與 `.claude/harness/learning/usage.json` 的 `items["harness:<檔名>"].view` | 整份檔有沒有被讀。這類項目第一次被讀才登記，**沒有這個 key＝裝學習迴路以來從沒被讀過** |
| 專案 skill 被讀／叫用 | `items["skill:<名稱>"]` 的 view／use；`J.usage.retireCandidates` | skill 有沒有被用 |
| 規則觸發次數 | `J.usage.ruleHits`、`J.usage.rulesNeverHit`（key 是 `<hook>:<規則 id>`，只涵蓋 `guard-risky-command` 與 `guard-test-preconditions`） | 文字規則對應的機械規則有沒有擋過東西 |
| 知識筆記被讀 | `items["knowledge:<路徑>"].view` | relocate 的目的地是不是真的有人讀 |
| 被擋與被糾正 | `C.denialsByTag`、`G.corrections` | 規則管的那件事實際發生過幾次；同一件事被糾正兩次以上＝文字沒防住，傾向 automate |
| 必讀有沒有讀、agent 有沒有被派 | `D.missingReads`、C 的派工清單 | agent 檔與必讀清單上的檔是不是真的進了 context |
| 事故來源 | 該檔的變更紀錄、F 踩坑區、memory | 規則是從哪次事故長出來的 |
| 重複 | 在專案指令檔與全域 CLAUDE.md 搜同一條規則 | delete 或 rewrite（合併）的依據 |

用量資料的限制，寫進證據欄，不要略過：

- 只從學習迴路安裝後開始算，`requests` 小於試用期（`J.usage.trialRequests`）時零次不算證據。
- 只計整份檔的讀取，不知道讀了哪一節。CLAUDE.md、`.claude/rules/` 與 agent 檔是自動載入的，沒有讀取次數——這幾份的證據只能從觸發、被擋、被糾正、事故來源找。
- 零次觸發代表「沒有起作用的證據」，不代表「沒有用」：規則被安靜照做也是零次。擋罕見但嚴重事件的規則（熔斷清單、正式環境、刪資料）不因零次觸發判 delete；熔斷清單的項目在帳本裡只會是 retain、rewrite 或 automate。
- 沒裝學習迴路時寫「沒有用量紀錄」，裁決只靠其他來源；這時判 delete 要有重複或前提消失的證據，不能只靠「看起來沒用」。

收集結果裡的數字照鐵則 1 附出處；要引用沒在收集結果裡的 usage.json 欄位，直接讀那個檔，不要從逐字紀錄自己數。

## 刪除風險

每一列都寫，retain 也寫（寫的是「若刪掉」）：

- **高**：從事故長出來、沒有 hook 擋、刪了會再犯；或熔斷類
- **中**：有別的東西部分擋住（hook 只擋一種寫法、另一份檔也提到但不完整）
- **低**：另一處完整重複，或模型預設就會這樣做

風險欄寫一句「刪了之後，什麼情況下會出什麼事，還有什麼會擋住」。

## 輸出

第 2.7 步屬於只讀階段：subagent 把帳本寫到主對話指定的系統暫存目錄（`<系統暫存目錄>/harness-review-<今天>-ledger.md`）並回報路徑，不寫進專案。主對話到第 4 步寫報告時，把核對過的帳本存成 `<落點>/.claude/harness/reviews/<今天>-ledger.md`。內容：

1. **總表**：每份檔一列——條數、五種裁決各幾條、全部核可後的行數（前→後）。CLAUDE.md 另寫 §0 專案概要以外的行數前→後，對照 §5 清單 80 行的門檻。
2. **逐檔明細**：每份檔一張表

   | 位置 | 指令（摘要） | 裁決 | 新文字／目的地與讀取路徑／hook | 證據（出處） | 刪除風險 |
   |---|---|---|---|---|---|

3. **連動**：一個裁決牽動別處的（relocate 要補路由表、automate 要補 hook 與 cases、合併要刪另一處），逐條列出，標明哪幾列要一起核可。

## 核可與套用

帳本裡每一列都是紅區提案（05 §1），使用者核可的才做，可以整檔、整種裁決或逐列挑。套用照 review 第 5 步第 8 段：

- relocate：同一次改動把讀取路徑補上；套用後實際驗一次讀取路徑——路由表那列指到的檔存在、`paths:` 的 glob 比對到檔、hook 注入有 case 證明會印出。
- automate：hook 補 cases（證明舊版放行、新版擋下），跑 probe-hooks 兩條路徑；原文縮成指向那支 hook 的一行或刪掉。
- 每份改到的檔照 05 §4 寫變更紀錄，寫明出自哪一份帳本。
