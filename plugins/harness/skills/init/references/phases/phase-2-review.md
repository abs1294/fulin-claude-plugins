## Phase 2 — 攤開核對（一則訊息，讓使用者糾正事實）

把 Phase 0 與 Phase 1 的結果攤成**一張盤點表**給使用者看，並附上「據此自動推導的預設」。這一步不是提問，是**讓使用者在生成前糾正事實錯誤**——盤點是推論，使用者才知道真相（例：某個 `deploy` 腳本其實早已廢棄）。

內容（下列項目名稱是給你的清單；攤給使用者時照「對使用者講話的寫法」改成白話，例如「危險動作候選清單」寫成「做了收不回來的動作，我找到這幾個」）：

0. **專案概要草稿（放最前面）**：從第 13 項整理，照下面格式；每句附出處，並明講「這是我讀文件推的，請直接改」。這份草稿確認後會寫進 CLAUDE.md，之後每個 agent 都靠它理解專案，所以錯的地方現在不改，之後會一直錯下去
   ```
   ## 這是什麼專案（我讀文件推的，請直接改）
   - 用途：<一兩句：給誰用、解決什麼問題>（出處）
   - 串接的外部系統：
     | 系統 | 做什麼 | 方向 | 讀或寫 | 程式裡的位址 | 正式還是測試 |
     | 物流商 API | 建立出貨單 | 我方呼叫對方 | 寫 | settings.py:22 的預設網址 | 看不出來，等一下問你 |
     | 物流商狀態回呼 | 通知出貨狀態 | 對方打進來（routes/webhook.py:8） | 寫（更新出貨單） | 對方設定的回呼網址，程式裡看不到 | 看不出來，等一下問你 |
     | 金流商撥款 | 對帳 | 不適用 | 讀（人工下載檔案後上傳，不走網路） | 無 | 不適用，不用問 |
   - 業務流程：<代號＋一句話，每條註明「已實作／部分實作／還沒做」與依據；部分實作寫出缺哪一段>
   - 目前進度：文件寫 <…>；實際 <…>（依據）
   - 過時的文件：<檔名：哪裡跟實況不符>
   ```
1. 十三項盤點表（每項附證據路徑；查不到的明寫「查不到」；第 12 項非參考模式時不列；第 13 項已整理成上面的概要，表裡只寫「見專案概要」）
2. Phase 0 的版本比對與五項檢查結果（參考模式另附備份位置與比對結果；0-3 使用者選不裝 Codex、0-5 使用者選不裝 git-commit 的，寫明是使用者的決定）
3. 自動推導的預設：
   - 前端分類與對應處置
   - Q1 預設 pipeline 依裁切規則裁完的樣子（先給出，Q1 再讓使用者改）
   - 危險動作候選清單（Q2 的題目來源；參考模式含原有 hook 在擋的東西）
   - 是否觸發 Q3（無前端）、Q6（無測試基礎）
4. 發現的目標專案自身問題（文件漂移、缺測試基礎、敏感物未被 `.gitignore` 擋）
5. **原有設定怎麼處理**（僅參考模式）：每一項一列，照下面格式。使用者在這裡改處置，改了就照改的做

```
| 原有的東西 | 它在管什麼 | 我打算怎麼處理 | 處理後在哪裡 |
| CLAUDE.md 的「部署前要先跑 smoke test」 | 部署前的檢查 | 搬過去（這是專案事實） | 新 CLAUDE.md「絕對邊界」一節 |
| CLAUDE.md 的「改完直接 commit」 | 開發流程 | 換成新流程（改完要先實測、再審查） | 新 CLAUDE.md 的開發流程圖 |
| .claude/agents/reviewer.md | 程式碼審查 | 合併進 code-reviewer（程式碼審查），它的檢查清單搬過去 | .claude/agents/code-reviewer.md |
| .claude/hooks/block-prod-db.js | 擋連正式資料庫 | 保留，繼續接著 | 新 settings 照原樣接線 |
| .claude/commands/deploy.md | 部署指令 | 不動 | 原位 |
```

   表格下面一句話講備份在哪、怎麼還原（「整份原樣在 `.harness-backup/<時間>/`，要還原就把裡面的檔案複製回原位」）。
6. **原有規矩裡的經驗**（僅參考模式）：第 12 項挑出的每一條一列，欄位「經驗｜出處｜它防什麼｜現在怎麼擋｜照預設處置會帶到哪（或：不會帶到）」。這裡只攤出來讓使用者糾正（漏列的、其實已經不適用的），「不會帶到」的在 Q8 問要不要升格。對使用者這樣講：「新的規則文件和自動檢查會照 harness <版本> 重新產生；你原本規矩裡這幾條是這個專案自己累積的經驗，通用規則裡沒有。已經會帶過去的我標出位置；不會帶到的，等一下訪談問你要不要升格成新規則的一部分。」

訊息開頭先用兩三句講結論（這是什麼專案、有沒有前端與測試、找到幾類做了收不回來的動作），再接上面各項（第 0 項專案概要一定放第一個）；整則訊息的**最後一句**固定是：「以上事實有錯請直接指出；沒有的話我開始逐題訪談（共 N 題）。」使用者糾正的事實回 Phase 1 重查確認後更新表格。**無人值守（headless）時**：照推導預設繼續，所有推導值在收尾回報列為「已代決」供事後否決；專案概要照草稿寫進 CLAUDE.md 但標「未經使用者確認」；第 13 項②的外部系統與資料庫全都沒經使用者確認，**一律當正式環境處理**（寫入動作全數列入 Q2 候選、照正式環境設規則），寧可多擋，不准自己判成測試環境；U3 的候選詞不寫進 GLOSSARY.md（既有專案沿用 CONTEXT.md）（沒人確認過的定義不算詞條），列在收尾回報等使用者確認。

**出關**：核對表送出、使用者糾正的事實都回 Phase 1 重查並更新過（無人值守：照推導預設繼續），跑 `init-flow.js advance <目標> 3` 進 Phase 3。無人值守時，之後每一題的代決答案照樣用 `init-flow.js answer` 寫進答案檔、加 `"delegated":true`。
