## 操作規則（怎麼操作才不會誤判）

> 收：UI／介面操作上「照直覺做會得到錯誤結論」的規則。格式：**規則一句話** ＋ 為什麼（症狀是什麼）。

- （示範）**等待資料載入完成再斷言，不要用固定秒數 sleep**。症狀：本機快時綠、CI 慢時紅，看起來像偶發失敗，實際是斷言跑在資料回來之前。

## 測試坑（照著寫會壞的寫法）

> 收：測試程式碼本身的坑——定位器、資料準備、teardown、時序。格式：**症狀** → **根因** → **正確寫法**。

- （示範）**症狀**：測試單獨跑綠、整批跑紅。**根因**：前一支測試的資料沒清掉，後一支查到兩筆。**正確寫法**：自種自清，teardown 只刪自己建的那筆（用建立時取回的 Id）。

## 設計知識（測什麼、測到多深）

> 收：測試設計上的判斷——哪類改動必須測哪個面向、哪些情境容易漏。格式：**觸發條件** → **必測項**。

- （示範）**動到日期／時間欄位** → 必須走真實 UI 輸入驗證，四點一致：UI 輸入值 → 送出的 payload → 資料庫實值 → 重新整理後的顯示值（手寫 API payload 通常剛好避開時區換算）。
