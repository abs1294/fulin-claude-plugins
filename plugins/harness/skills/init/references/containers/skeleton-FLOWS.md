> **收錄原則**：只收「踩過坑」或「橫跨 ≥2 個{{模組單位，例：repo／服務／模組}}」的鏈路，**每條掛事故收據**——這不是全量架構文件，是防「跨層漏同步」的地雷圖。層級路徑寫進來前要實地查證，修改前仍以程式碼現況為準。
>
> **維護紀律**（正本＝`.claude/harness/04-delegation-templates.md` 共通規則）：
> - 動到本檔已收錄鏈路上任一層的任務，**開工前必讀本檔**。
> - 完工報告**必答「鏈路其他層是否需同步」**（答「不需要」也要附一句理由）。
> - 新事故涉及新鏈路時，隨 memory 一起補進來（同步補本檔 Changelog 一行）。
>
> 為什麼要有這份：跨層漏同步的失敗形狀幾乎都是**靜默吞掉、不報錯**——加了一個欄位，四層只同步了三層，中間那層把它丟了，畫面上就是「沒顯示」，看起來像前端的錯。

### 鏈路條目格式

```
## 鏈 N：<一句話講這條鏈在做什麼>

<層與層的流向，一行箭頭圖>

| 層 | 檔案 | 關鍵點 |
|---|---|---|
| <層名> | <路徑> | <這一層容易漏什麼／規律是什麼> |

**⚠️ 動這條鏈的紀律**：<動哪裡要同步哪裡>
事故收據：<一句話講發生過什麼、後果是什麼——不寫日期，寫機制>
```

## （示範）鏈 1：前端顯示後端新增欄位

```
資料庫欄位 → 資料存取層映射 → API 回應 DTO → 前端 API 模組 → 畫面元件
```

| 層 | 檔案 | 關鍵點 |
|---|---|---|
| 資料存取層映射 | `<後端資料存取層路徑>` | 手寫映射時新欄位不會自動帶出 |
| API 回應 DTO | `<DTO 路徑>` | 序列化只輸出 DTO 上有的欄位，漏加＝前端永遠拿不到 |
| 前端 API 模組 | `<前端 API 模組路徑>` | 若有欄位轉換（命名風格轉換），確認新欄位有經過 |
| 畫面元件 | `<元件路徑>` | 顯示欄位清單通常是另一個設定陣列 |

**⚠️ 動這條鏈的紀律**：加欄位給畫面看＝**四層全同步**，漏任何一層都是靜默吞、不報錯。
事故收據：（示範）新增欄位只同步了三層，DTO 漏加，畫面顯示空白，被當成前端問題查了一輪。
