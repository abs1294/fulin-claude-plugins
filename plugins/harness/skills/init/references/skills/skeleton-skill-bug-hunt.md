# 難 bug 診斷

紀律正本不在本檔：停損信號＝`03-judgment-matrix.md` 矩陣 A（A1 同一個錯誤第 3 次、A5 投入很多次工具呼叫卻沒進展、A6 懷疑環境之前要先有證據）；跑整合或畫面驗證前的三項環境驗證＝03 的 B13；修完補回歸測試＝03 的 B14；卡關往上交接時的失敗軌跡格式＝`02-model-dispatch.md` §4；踩坑紀錄格式＝`05-knowledge-protocol.md` §2。本檔只把它們串成步驟。

## 第 0 步 — 先驗環境（整合、畫面類的 bug 必做）

照 03 的 B13 三項各貼原始輸出：聽那個埠的是不是你要測的那套服務 → 它跑的是不是你改過的程式 → API 真的回你要的欄位。**每一批測試前重驗**。{{有產生本機覆寫說明時加（＝第 5 題保留了本機覆寫保護；Q5 取消了就整段刪掉，不准指向不存在的說明檔）：服務起不來、端點整批回授權錯誤、測試信寄出去這類症狀，先照 03 的 A9 查本機覆寫還在不在（值與症狀見 `.claude/harness/local-overrides-guide.md`）。}}

## 第 1 步 — 建回饋迴路（整個 skill 的重點，其餘是機械操作）

目標：**一條指令讓 bug 變紅**。下面四項同時成立才算建好：

- [ ] **能變紅**：打到真的 bug 路徑，斷言使用者描述的**確切症狀**（「跑起來沒報錯」不算）
- [ ] **確定性**：同樣的輸入、同樣的判定；時好時壞的，先把重現率拉高再往下
- [ ] **快**：分鐘級以內（要跨網路的環境不強求秒級）
- [ ] **執行者自己能跑**：執行迴路的那個 agent 自己重跑、自己貼輸出（轉述別人的輸出不算跑過）

**迴路建起來之前，禁止讀程式碼建理論。** 讀碼推出來的原因，在有迴路之前沒有任何方法證明或推翻。

本專案迴路配方（先套用，套不上再自己發明）：

- {{單一測試：只跑一支、一個案例的指令，例：npm test -- -t "<案例名>"}}
- {{直接打 API：例：curl 打本機服務的端點，斷言回應裡的業務狀態欄位而不是 HTTP 狀態碼}}
- {{讀回資料庫實值：用本專案確認過的測試帳號與連線方式（密碼從環境變數帶），讀出寫入的那幾欄}}
- {{畫面層的 bug：整段交給測試角色（qa-engineer）自己建迴路、自己跑、自己貼——瀏覽器操作照它的紀律}}

建不出迴路時：

- **停下來明講**，列出試過哪些方法、各卡在哪，向使用者要能重現的東西（瀏覽器匯出的 HAR 檔、伺服器 log、錄影、出事那筆資料的識別碼）。不准沒有迴路就開始猜。
- 人一定要在迴圈裡（例：要實體設備、要使用者帳號才看得到）是最後手段：把人的操作寫成結構化的步驟清單，一輪一輪請使用者照做並回報結果。

**輸出遮罩（每一步都適用）**：貼指令輸出、錯誤軌跡、API 回應之前，憑證一律改寫成 `<REDACTED>`——連線字串裡的密碼、權杖、`Authorization` 標頭、cookie。迴路指令用環境變數帶憑證，讓密碼留在環境裡、不進輸出。遮罩後資訊不夠診斷時明講並問使用者，不得為了方便貼原文。

## 第 2 步 — 重現＋縮小

跑紅一次，確認紅的是使用者描述的**那一個**失敗，不是隔壁的。接著一刀一刀砍：輸入、呼叫端、資料、設定，每砍一刀重跑，直到留下的每一樣都是缺了就不紅的。

## 第 3 步 — 假設（先列後測）

**先列 3～5 個排序過、可以被推翻的假設，才准測第一個**——只想一個假設，會被第一個看起來合理的想法綁住。每個假設寫成預測：「若 X 是主因，改 Y 應該讓 bug 消失；改 Z 應該讓它更嚴重」。講不出預測的假設丟掉。

假設清單給使用者看（他有領域知識，常能一眼排出順序）；使用者不在就照自己的排序繼續，不空等。想動環境（重啟服務、清快取、重裝套件）之前照 03 的 A6；同一個錯誤第 3 次出現照 A1 停下換路。

## 第 4 步 — 檢驗

一次只改一個變數。加的除錯輸出**一律帶固定前綴** `[DBG-<四碼隨機字>]`（例：`[DBG-7f3a]`），收尾時靠它一次找乾淨。效能類的問題先量基線再二分，不憑感覺。

## 第 5 步 — 修＋回歸測試（03 的 B14：紅 → 綠 → 驗證）

先在對的位置寫一支會紅的測試 → 看它紅 → 修 → 看它綠 → 回跑第 1 步的原始迴路。**先修再補測試＝沒完成**：測試沒先紅過，證明不了它鎖得住這個 bug。找不到對的位置寫測試，本身就是發現（架構擋住了），記下來回報。

## 第 6 步 — 收尾

- [ ] 原始症狀不再出現（回跑第 1 步的迴路，貼輸出）
- [ ] 除錯輸出清乾淨：`git grep -n "\[DBG-"` 0 筆
- [ ] 根因照 05 §2 的格式記進 memory（症狀 → 根因 → 動作）
- [ ] 命中的那個假設寫進 commit 訊息（下一個除錯的人用得到）
