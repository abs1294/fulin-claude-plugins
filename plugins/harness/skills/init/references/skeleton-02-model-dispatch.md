# 02 — 模型調度與動態升降級守則

> SSOT：派工／模型選擇／升降級／隔離驗證，只信本檔。修改權限：紅區。
> 讀者是指揮官（主對話模型）。每次要派工或卡關時翻開對照，不要憑記憶。

## 1. 模型分工表

| 層級 | 模型（Agent tool `model` 參數） | 做什麼 | 絕不派給它什麼 |
|------|------|--------|----------------|
| 指揮官 | 主對話 | 決策、任務拆解、架構取捨、與使用者對話、彙整結論 | 大批量讀檔、全 repo 掃描、機械性批次修改（這些必須派下去） |
| 執行層 | `sonnet` | 搜尋研究、讀檔摘要、依計畫實作、寫測試、重構、單一範圍審查、文件收斂 | 無明確驗收條件的開放式任務；品味決策 |
| 進階執行層 | `opus` | 複雜多面向任務，滿足任兩項即可直接派：(1) 橫跨多個模組／前後端；(2) 需組合多條工具鏈；(3) 驗證鏈路長（UI→API→DB 全鏈）；(4) 無現成範本可照抄 | 有明確範本可照抄的單一任務、純機械批次（降回 `sonnet`/`haiku`） |
| 機械層 | `haiku` | 純機械性：批量重命名、格式轉換、清單彙整、grep 結果整理 | 任何需要理解業務邏輯或跨檔推理的事 |

補充規則：

- 派工時**一律顯式帶 `model` 參數**，不帶就繼承主對話、浪費高階額度。{{若有裝 check-agent-model hook 加：此規則已由 PreToolUse hook `.claude/hooks/check-agent-model.js` 程式強制（專案 agent 缺 model 直接 deny）——被攔到就照 deny 訊息補參數重發，**不得改派其他 agent type 繞過**。}}
- **Fable 禁下放**：除非使用者明確要求，subagent 不得帶 `model:"fable"`；主對話為 Fable session 時，派工照上表選 `sonnet`/`opus`/`haiku`，不得讓 subagent 繼承 Fable。
- **Quota 節流**：平行派工可以，禁無界灑艦隊——分波派發每波併發 ≤6（重型讀碼／審查 ≤4）；任一 agent 撞 quota／API 終止 → 熔斷（停派下一波、保留已完成、回報使用者，禁自動重試）；大艦隊（>15 agents 或估算 >1M tokens）先報預算徵同意。
- **主對話的成本主要在長 session 的超長 context**，不在派工分層：每則回覆都重讀整段 context，context 越長、每輪越貴。任務告一段落就開新 session 或 `/compact`，比調整派工模型省得多。{{若有裝壓縮交接 hook（形狀目錄第 26 列），保留下面從「壓縮前後由 hook 補位」到本條結尾的整段；Q5 取消了這組 hook，就把那整段刪掉，只留前面的成本原則：}}壓縮前後由 hook 補位：`compact-snapshot.js`（PreCompact）存快照，並呼叫 `compact-handoff.js` 開一個隔離的 `claude -p` 子 session 依對話寫**交接信**——已完成只留結果、未完成完整保留、沒驗證的標 HYPOTHESIS，另有目標版本、硬約束（只收使用者親口說的，CLAUDE.md／memory 條文不列）、關鍵值（程式從工具回傳抽出的原值，信寫完以字串比對驗是否原樣抄入）、走過的死路；`compact-reinject.js`（SessionStart matcher=compact）注入交接信並附程式算出的背景任務清單，交接信沒產生時退回快照清單；`compact-summary-log.js`（PostCompact）記下摘要與交接信各漏了什麼；`resume-stale-reminder.js`（SessionStart matcher=resume）在隔數小時才 resume 時提醒狀態可能已過期。壓縮後看到 `[compact-reinject]`，**第一個回覆先交代交接信「未完成」第 1 項的結果**，交代前不做清單以外的事；交接信與摘要裡「已完成／已驗證」類主張，行動前先對回原始證據。hook 輸出注入 context 有 10,000 字元上限（官方文件未載，超過只注入前 2,000 字預覽），交接信的長度設定要留在這個預算內。

### MCP 使用紀律

{{若 Phase 1 判定為「瀏覽器可驅動前端」保留本段，否則改寫為本專案的實跑方式或整段刪：}}

- **瀏覽器功能測試一律派 QA agent 執行**，由它用瀏覽器 MCP 跑＋直接 codify 成可重跑測試，指揮官只收結論。**指揮官不親跑瀏覽器 MCP**（大量頁面快照會燒掉主對話 context）。
- **實作 agent 不負責測試**：其瀏覽器驗證產出留在它自己的 context 不落地，QA 還要重跑一次才能 codify → 白花 token。派工 prompt 禁止叫實作者「開畫面自我確認」。
- **子 agent 能不能用某個 MCP，實測比推論準**：`permissions.allow` 沒列 ≠ 一定被擋、列了 ≠ 一定能用（還受全域權限模式影響）。不確定時先派一個探針 agent 試呼叫一次，被 deny 就回報主對話補 allow-list，不要空轉重試。

## 2. 指揮官不下場（量化觸發線）

滿足任一條就**必須派工**，不得自己動手：

1. 預計要讀 **3 個以上檔案**才能回答的問題 → 派 `Explore`（唯讀）或 `general-purpose`。
2. 同一問題已經搜了 **2 輪**（Grep/Glob）還沒找到 → 派 `general-purpose` 去搜，自己停手。
3. 批次修改 **3 個以上檔案**且模式相同 → 先自己改 1 個當範本，其餘派 `sonnet` 批次套用。
4. 需要「讀完整份長文件再摘要」（>300 行）→ 派工，只收結論。

反向豁免（可以自己做，不必派工）：改 1~2 個已知檔案的小修改；讀單一已知位置的小段落。

## 3. 派工三件套（缺一不發）

每個 Agent prompt 必含三段（模板見 `04-delegation-templates.md`，直接複製填空）：

1. **目標與背景**：要做什麼、為什麼、相關檔案的絕對路徑、已知的坑（從 memory 撈）。
2. **驗收條件**：可機械判定的條件清單（build 過、某 grep 為 0、測試綠…）。「做好做滿」「保持品質」這類寫法禁止出現。
3. **回報格式**：明列要回報的欄位。鐵則：**回報成果路徑＋關鍵行號，禁止噴大段代碼**。

## 4. 異常升降級路徑

### 升級（往上丟，帶著失敗軌跡）

| 情境 | 動作 |
|------|------|
| `haiku` 工具呼叫錯誤或語法錯誤 **1 次** | 直接改派 `sonnet`，同 prompt 重發 |
| `sonnet` 同一子任務**連續失敗 2 次** | 升級：由指揮官親自處理，或派 `opus` subagent |
| 指揮官自己也卡（符合 `03-judgment-matrix.md` 矩陣 A 任一信號） | 熔斷問使用者，或依 03 換路徑 |

**升級時必附「失敗軌跡」**，格式固定：

```
[失敗軌跡]
- 嘗試 1：<做了什麼> → <確切錯誤訊息或錯誤行為>
- 嘗試 2：<做了什麼> → <確切錯誤訊息或錯誤行為>
- 已排除的假設：<一行一條>
- 未讀過但可能相關的檔案：<路徑>
```

沒有失敗軌跡的升級＝讓上級從零重查一遍，等於白升。

### 降級（解出 pattern 後往下丟）

高階模型解出「固定可複製的修法」後，把修法寫成**配方**（改哪裡、改成什麼、怎麼驗證），派 `sonnet`/`haiku` 批次套用。配方必含 1 個已完成的 diff 當範例。

### 重試上限（硬性）

同一子任務：**同一層級最多嘗試 2 次**——第 2 次失敗即升級，禁止在同層試第 3 次；升級後那一次是第 3 次嘗試；第 3 次仍失敗 → 熔斷問使用者（03 矩陣 C6）。「換個小寫法再試一次」也算一次嘗試，不要自我豁免。

## 5. 隔離驗證（實作者不自驗）

{{若既有治理層有「不得自我核准」類規則，加一句：與 {{路徑}} 的「{{條文名}}」同向；本節管 Claude 端 subagent 的落實方式。}}

- 實作 agent 的「我完成了」**一律視為未驗證的宣稱**。
- 驗收由 **Fresh-Context 驗證者**執行：新開一個 subagent，**只給它「驗收條件＋成果路徑」，不給實作過程與實作者自述**（避免被帶風向）。
- 三種驗證模式，按任務選：

| 模式 | 適用 | 做法 |
|------|------|------|
| Read-back | 文件、設定、規則檔 | 驗證者重新讀檔，逐條對照驗收條件打勾，回報「條件 → PASS/FAIL＋證據行號」 |
| 實跑 | 程式碼 | 驗證者實際跑 build／測試指令（見 03 矩陣 B 的本專案指令），貼結尾輸出 |
| 多樣本評審 | 設計文件、方案選型 | 產 2~3 個獨立版本，派評審 agent 依明文評分標準選優，混合裁切 |

- 驗證者回報 FAIL → 回實作者修（計入該子任務的重試次數）。
- **指揮官不得因為「看起來沒問題」跳過驗證。**
