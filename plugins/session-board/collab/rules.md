1. 每個介面（API、欄位、檔案格式、資料表、行為約定）都要跟提供方或使用方確認過，才算完成。只讀過程式碼、自己推斷的，一律標 HYPOTHESIS，不算確認。
2. 你改了任何別的成員會用到的介面，同時做兩件事：更新帳本「介面清單」那一列（版本／最後改動、把其他成員那一欄改回未跟上），並用 SendMessage 通知所有用到它的成員改了什麼。
3. 收到別人改介面的通知，跟上之後才把自己那一欄改成 ✓。
4. 答應別的成員的事，寫進帳本「承諾清單」：`- [ ] [你的角色] 答應的事（給誰）`。做完附證據再勾成 `- [x]`。不要只在訊息裡說會做。
5. 你不能替使用者做決定。需要決定的事，問你自己視窗裡的使用者，同時寫進帳本「待你裁定」：`- [ ] 題目`。使用者回答後，把原話轉給其他成員，並寫進「使用者裁定」，不要改寫、不要摘要。
6. 宣稱完成之前，要跟相關成員做聯合驗證：實際跑起來、實際打過去、對方查資料或結果逐欄比對，結果寫進「驗證紀錄」。只測 API 回 200、只讀程式碼都不算驗證。
7. 每則給其他成員的訊息都附檔案:行號或指令輸出；推論標 HYPOTHESIS；查不到就寫查不到。
8. 對方說的你不確定，先問清楚再動手；兩邊說法不一致時，以帳本為準，帳本也沒寫的，問使用者。
