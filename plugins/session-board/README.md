# session-board

**Claude Code 的圖形介面。** 這台電腦所有的 Claude Code 對話，在同一頁開、看、接著做：左邊是清單，右邊是對話，下面打字。手機和另一台電腦也能用（透過 Tailscale）。

- **外掛整合進來**：goal2 交辦、harness 健檢與它畫的流程圖、沒 commit 的改動、外掛的推薦與安裝、排程、LINE 小秘書，都在畫面上按，不用記指令。
- **輸出看得懂**：表格、程式碼上色、Word／簡報／PDF／網頁直接在旁邊打開，對話裡的檔案、連結、指令、localhost 網址都按得動，不再是一整面終端機文字。
- **訊息替你理好**：Gmail、Teams、Slack 判讀成「要你處理的」，帶著附檔派進對的專案、對的對話；上班日早上用 LINE 告訴你今天要做什麼、還有什麼沒做，送之前先核對你做了沒。
- **不用一直盯著**：誰在等你、誰卡住、誰做完了，一眼看到；額度用完會等恢復、被中斷會接著做、關機後開得回來、幾個 session 可以一起完成一個目標。

它是只在本機開的網頁：單一 Node 程序，沒有相依套件，看板自己的資料都存在你的電腦（`~/.claude/session-board/`）。

## 兩種 session

| | 在哪裡跑 | 在看板上能做什麼 |
|---|---|---|
| 看板裡的對話 | 看板自己開的背景程序，沒有終端機視窗 | 直接打字對話、核准或拒絕 Claude 要做的動作、停止 |
| 終端機 session | 你自己開的 Windows Terminal 視窗 | 看它的對話（唯讀）、把它的視窗切到最前面 |

同一個 session 不會兩邊同時跑。終端機 session 可以「搬到這裡對話」（會先結束終端機裡的那一個），看板裡的對話也可以「移到終端機」（有還沒送出的字、暫存、還沒送出的附件或 Claude 沒讀到的訊息時不移，會說是哪一種：移過去就拿不回來）。

左邊清單依資料夾分組，每個 session 前面的圓點：橘色是輪到你（等你回應、做完等你指示、有你還沒看的回覆），綠色是 Claude 正在跑，灰色是沒事。瀏覽器分頁標題會顯示輪到你的數量。

## 對話畫面裡的操作

- **回到我上次說話的地方**：對話右下角的「↑ 我上一則」跳到你上一次說話的位置，再按一次再往上一則；「↓ 最新」回到最底。打開一個對話時，如果你最後一句話之後的回覆比畫面長，會直接停在你那句話，方便從那裡往下讀。
- **暫存（Ctrl+S，Mac 的 ⌘S 也可以）**：框裡有字就收起來、先說別的；框是空的就還原（游標也回到原位）；兩邊都有就對調。送出別的訊息後自動還原。一個對話一格，文字存在看板上，附的圖和檔案只留在這一頁。輸入框上方會列出暫存了什麼；＋ 選單也有。
- **斜線指令清單**：在輸入框打 `/` 加幾個字（例如 `/pl`），上方會列出名稱符合的指令，用上下鍵選、Enter 或 Tab 帶入。清單是直接向 Claude Code 問「這個資料夾」的：每個資料夾裝的 plugin、專案自己的指令都不一樣，所以不猜、也不借用別的資料夾的。做法是在那個資料夾啟動一個 Claude Code 程序、送一個查詢請求、拿到答案就結束它，約一到兩秒，不會送出任何訊息，所以不花額度、不留對話紀錄。答案保留 10 分鐘，之後再問一次（期間裝或移除 plugin 最慢 10 分鐘後反映）。每個指令附說明與參數提示。`/plugin`、`/config`、`/resume` 這類終端機裡的互動畫面在看板裡不能用，會列出來並標「只能在終端機用」。
- **搬到這裡對話時會順手關掉終端機視窗**。只有在剛好一個視窗對得上時才關；對不上、或有兩個視窗標題相同，就不關並在畫面上說明。視窗裡還有其他分頁時，Windows Terminal 會自己問你要不要一起關。

## 語音輸入

輸入框旁的麥克風：按一下開始說，說完再按一次。

- **誰來聽**（設定 → 語音輸入）：瀏覽器內建的辨識（免費，Chrome 會把聲音送到 Google），或 OpenAI 轉錄（用你自己的 API 金鑰、自己付費，說完才出字）。
- **自動排版**：說完交給 Claude（sonnet）去掉贅字、補標點，約 1 秒；整理不成就保留原話。滑鼠移到麥克風上，上方會浮出一個小開關可以直接切換；設定頁也有同一個開關。錄音與排版進行中不顯示，觸控螢幕上不顯示。
- **詞庫是一個專案一份**：輸入框左邊的 ＋ →「語音對照表」打開的是這個對話所在專案的詞庫，存在 `~/.claude/session-board/vocab/`，不跟別的專案共用。裡面有你加的詞、從你的修改學到的聽錯（麥克風排好的字你改過再送出，例如「哥特」改成「git」，下次就會自己改對），以及看板從這個專案的資料夾與對話標題自動收集的英文名稱。提示辨識器、OpenAI 轉錄的關鍵字、自動排版，用的都只有這個專案的詞庫。不在任何專案資料夾裡的對話沒有詞庫。
- 以前所有專案共用一份（`~/.claude/session-board/vocab.json`）。那份還在的話不會自動套用，語音對照表裡有一個按鈕可以把它複製進目前的專案。

## 檔案預覽

回覆裡提到的檔案路徑，只要那個檔案真的存在，就會變成可以點的（有底線）。點了在右邊滑出預覽，不用自己去找檔案。

| 檔案 | 怎麼顯示 |
|---|---|
| 圖片、PDF | 直接顯示 |
| 文字、程式碼、Markdown、JSON、log | 直接顯示（Markdown 會排版；超過 2 MB 只顯示前 2 MB） |
| Word、Excel、PowerPoint | 由這台電腦的 Office 在背景轉成 PDF 再顯示。第一次約 10 到 30 秒，之後直接顯示；檔案改過會重新轉 |
| 其他 | 不能預覽，但可以「在檔案總管顯示」 |

預覽面板上有三個按鈕：用預設程式開啟、在檔案總管顯示、複製路徑。按 Esc 關閉。面板的左邊緣可以拖拉調整寬度（最窄 320，最寬留 160 給左邊），寬度記在這個瀏覽器裡；在邊緣按兩下恢復預設。

- 絕對路徑（`C:\...`）和相對路徑（`src/app.js`、`src/app.js:42`）都認得；相對路徑以該 session 的資料夾為準。
- 回覆只寫檔名（`報告.pptx`）而檔案其實在好幾層子資料夾裡時，會在該 session 的資料夾底下依檔名找。同名的有好幾個就取最近修改的那個，滑鼠停在連結上會說明。這個搜尋只在該 session 的資料夾內進行，有深度（7 層）、數量（4 萬個項目）與時間（1.5 秒）上限，跳過 `node_modules`、`.git`、`bin`、`obj` 這類資料夾；session 的資料夾如果是磁碟根目錄或家目錄，就不搜尋。
- 「用預設程式開啟」只開文件、圖片與純資料類型。腳本與程式（`.ps1`、`.bat`、`.exe`、`.js` 等）不從看板直接開啟：路徑是 AI 寫出來的文字，不能讓點一下就執行東西。
- 轉出來的 PDF 放在 `~/.claude/session-board/preview-cache/`，超過 7 天自動清掉。原檔以唯讀開啟，不會被改動。
- `.html` 一律當成文字顯示原始碼，不會當網頁執行。
- 外面來的檔案不當成可信的：預覽 Office 檔時巨集一律關閉；信件附檔與內文圖片存檔時加上「來自網際網路」的標記（之後用 Office 開會進受保護的檢視）；會執行東西的類型（`.html`、`.svg`、含巨集的 `.docm`／`.xlsm`／`.pptm`）不提供「用預設程式開啟」；網路路徑（`\\主機\共用`）一律不處理。

## 戰情室

左上角的「戰情室」。最上面是它的主要用途：**每月用量與 API 等值費用**。

- 範圍是一個日曆月（1 號到月底，本機時間），可以往前翻月份。
- 算的是這台電腦上**所有** session：開著的、已經關掉的、主對話、子代理，全部。
- 顯示：API 等值費用（照官方牌價換算，不是訂閱實際被收的錢）、總 tokens 與四種 token 的拆分（輸入、輸出、寫入快取、讀取快取）、每天平均、照目前速度到月底的推估、每天一根的長條圖、各模型、各專案（session 啟動的資料夾）、各 session。
- 怎麼算：把 **cc-statusline**（1.10.0 以上）的每則用量紀錄加起來，看板不自己讀對話紀錄算用量、不自己計價。每一次模型呼叫依它自己的時間歸到某一天；同一次呼叫在對話紀錄裡會出現好幾次（每個內容區塊各寫一次、子代理的會抄進主對話、分岔出去的 session 會整份複製），cc-statusline 只算一次。沒裝或太舊時這一頁會說要安裝或更新。
- 本月的數字超過 1 分鐘會重算；也可以按「重新計算」。過去的月份存在看板的資料庫（每個月一筆），隔一天以上再打開時重算；月底最後幾筆還沒收進來的，收進來之後就會補上。0.21.0 之前存下的月份可能含 cc-statusline 收不到的（對話紀錄已經被清掉），不會被變小的蓋掉。

- 長條上點兩根就是起訖（或直接拖曳），下面的各模型、各專案、各角色、各 session 和匯出 CSV 就只算那幾天；滑鼠移到一根上有「摘要」，照 daily-report 的寫法寫那一天做了什麼，存起來以後可以再看。

最下面是**各 session** 一張表：本月有用量的每個 session 的本月費用、佔比、tokens，花費高的在上；預設顯示前 15 個加上所有還開著的，可按「顯示全部」。還開著的 session 前面有圓點，另外顯示壓縮次數、目前 context、訊息數，點一列打開那個對話。

帳號額度固定顯示在左側欄底部；誰正在執行看左側清單的圓點。

舊平台的戰情室還有「今日呼叫數／今日花費」和單次呼叫的「收據」面板，這裡刻意沒有：前者從現有資料算不準，後者就是對話本身，點進去就看得到。

## 每個對話上方的數字

打開任何一個對話，標題下面有一列：花費、用量、壓縮次數、目前 context、訊息數，有子代理在跑時多一項。滑鼠停在上面有細目（例如花費分成主對話與子代理）。按「更多」看子代理總數、常用 skill、MCP 呼叫次數、最近改過的檔案。

數字的來源與限制：
- **花費、tokens**、壓縮次數、訊息數、子代理、skill、MCP、改過的檔案，都是 **cc-statusline** 算好寫下來的，看板只是讀，在終端機或看板裡跑都一樣。花費是「整個對話從開始到現在的累計（含子代理）」，照官方牌價換算；前面有 `~` 表示其中有暫估單價。context 用量也是它算的（1.10.0 起）。cc-statusline 1.10.0 起每次回覆完就更新；更早的版本只在終端機裡更新，這時看板改用它的全機明細（1.9.x 最多慢 6 小時），滑鼠停在上面看得到更新時間。不用 Claude Code 自己回報的金額：對話接回來之後它會把之前的再算進去。
- **context 佔比** = 最近一次回覆時送給模型的內容量（輸入加快取）÷ 該模型的上限。上限是看板從自己跑過的對話得知的（每輪結果會附），記在 `models.json`。沒跑過的模型：用量超過 20 萬就只可能是 100 萬的上限（會標「推定」）；否則只顯示 tokens、不顯示百分比。資料夾設了 `autoCompactWindow` 的，上限以它為準（讀設定檔：環境變數、`settings.local.json`、專案、使用者，含各模型自己的設定）。狀態列顯示的百分比是 Claude Code 直接給的，兩者可能差一兩個百分點。
- **壓縮次數**來自 cc-statusline；沒被壓縮過顯示 0 次。
- **5 小時與 7 天額度**是整個帳號共用的。由 cc-statusline（1.9.0 以上）收集：每次問答結束在背景向 Claude Code 查一次（5 分鐘內不重複、不花 token），存在 `~/.claude/cc-statusline/state/account-limits.json`，看板只讀這一個檔。沒有問答時數字會是舊的，畫面會註明是多久前的。

## 開新對話

按「＋ 新對話」，三種方式選資料夾：跳出 Windows 的資料夾選擇視窗、貼上路徑、或點一個用過的資料夾。也可以按清單裡資料夾名稱旁的「+」直接在那個資料夾開。

看板裡的對話會記在 `~/.claude/session-board/channels.json`。看板重啟或重開機後它們還在清單上，再送一則訊息就接著原本的對話繼續。

## 使用

在 Claude Code 裡輸入 `/session-board`：一打就啟動看板並用瀏覽器打開（已經在跑就直接打開），回給你網址。也可以直接跑腳本；停止與查狀態只有腳本（停止時看板裡有對話在跑會拒絕並列出是哪幾個，加 `--force` 才會硬停）：

```bash
node plugins/session-board/scripts/start.js --open     # 啟動並開啟頁面
node plugins/session-board/scripts/start.js --status   # 查狀態
node plugins/session-board/scripts/start.js --stop     # 停止
```

預設埠 4317，可用 `--port <埠號>` 或環境變數 `SESSION_BOARD_PORT` 改。

看板程序是背景常駐的，重開機後要再啟動一次。plugin 更新後要 `--stop` 再啟動，新版才會生效。

## 安裝在 Windows 上

1. 需要：Windows 10／11、Windows Terminal、Node 22.5 以上、Claude Code。
2. 在 Claude Code 裡加入這個 marketplace 並安裝 `session-board`；想看到金額、壓縮次數、額度的話一併安裝 `cc-statusline`。
3. 重開 Claude Code（hook 要重開才生效），輸入 `/session-board`。看板會啟動並在瀏覽器開啟。
4. 想要重開機後自己回來：到「設定」打開「登入 Windows 時自動啟動看板」與「看板啟動時自動把常駐的 session 開回終端機」。
5. 收件是選用的，**預設關閉**：到「設定」→「收件」打開，再到「收件」→「抓取設定」把要抓的來源各自打開。沒打開的來源看板完全不會去讀（包括 Teams 的本機紀錄）。Gmail、Slack 另外要的東西見上面「給別人用之前要知道」。

## 安裝在 Mac 上

1. 需要：macOS、Node 22.5 以上（`brew install node`）、Claude Code（`claude` 要能在終端機直接執行）、內建的 Terminal。Python 3 只有用到 cbm-guard 的程式碼索引檢查時才需要。
2. 加入這個 marketplace 並安裝 `session-board`（建議一併裝 `cc-statusline`），重開 Claude Code，輸入 `/session-board`。
3. 第一次用到下列功能時，macOS 會跳出權限詢問，按「好」：
   - 「顯示終端機視窗」：要允許看板（node）控制 **Terminal**（系統設定 → 隱私權與安全性 → 自動化）。
   - 系統通知：通知由「指令碼編寫程式」送出，要在系統設定 → 通知裡允許它。
4. 想要登入後自己啟動：到「設定」打開「登入 Mac 時自動啟動看板」。它會在 `~/Library/LaunchAgents/` 放一個 `com.fulin.session-board.plist`，關掉就是刪掉它。
5. Word／Excel／PowerPoint 預覽要先裝 LibreOffice（`brew install --cask libreoffice`）。沒裝時預覽會直接說明，其他檔案照常預覽。

Mac 跟 Windows 不一樣的地方：

- 終端機 session 開在內建的 **Terminal**（不是 iTerm）。「移到終端機」「開回終端機」會開一個新的 Terminal 視窗。
- 看板「結束」終端機 session 或把它搬進看板後，會關掉原本的 Terminal 視窗；視窗裡還有其他分頁、分頁裡還有程式在跑，或不是內建 Terminal 的，就留著並說明。
- 點系統通知不會跳到那個 session（只有 Windows 有）。
- 收件的 Teams 來源讀的是 Windows 版 Teams 的本機紀錄，Mac 上沒有；Gmail、Slack 照常。
- Tailscale 遠端是選用的，預設關閉，不用設定。

安裝後 plugin 會在這台電腦上放的東西：`~/.claude/session-board/`（資料、設定、權杖）、目前使用者的網址類型 `sessionboard:`（通知開著時）、「啟動」資料夾的一個檔（自動啟動開著時）。解除安裝前先到設定頁把通知與自動啟動關掉，這兩樣才會移除。

## 通知

session 做完一輪、或需要你核准時，跳一則 Windows 通知；點通知會切到那個 session 的終端機視窗，看板裡的對話則開到看板頁面，那個 session 已經關掉就開看板首頁。

- 只通知你自己開的：終端機 session 與看板裡的對話。程式跑的（排程、其他工具呼叫 `claude -p`）不通知。
- 同一個 session 的新通知會取代舊的，不會疊一排。
- 由三個部分組成：`hooks/hooks.json` 的 Stop／Notification hook → `scripts/notify-hook.js`（決定要不要通知、通知寫什麼，規則在 `lib/notify.js`）→ `scripts/toast.ps1`（顯示）；點擊走 `sessionboard:` 網址類型 → `scripts/focus-click.js`。
- 每次點擊在 `~/.claude/session-board/focus.log` 記一行（點了哪個、做了什麼，不含標題與訊息內容），「點了沒反應」時看這裡。
- `~/.claude/settings.json` 裡已經有自己的通知腳本（Stop hook 執行檔名含 notify 的腳本）時，看板的通知不會跳，避免同一件事通知兩次。

## 給別人用之前要知道

這個 plugin 是照一個人的機器長出來的。別人裝起來，下面這些各自成立或不成立：

| 項目 | 別人的機器上 |
|---|---|
| 作業系統 | 只支援 Windows（要有 Windows Terminal 與 PowerShell）。其他系統啟動時會直接說明並結束 |
| Node | 22.5 以上（用內建的 SQLite） |
| session 清單、對話、常駐還原、沒開著的對話 | 可以用，不需要其他東西 |
| 花費、用量、context、每月用量、壓縮次數、額度 | 需要另外裝 cc-statusline（1.10.0 以上）；沒裝就沒有這些數字 |
| 自己結束 session 立即不常駐 | 裝成 plugin 後由 `hooks/hooks.json` 自動生效 |
| 收件：Teams | 要在抓取設定打開「抓 Teams」才會讀。只讀「個人帳戶」的 Teams 桌面版本機紀錄。哪個帳號是自己會自動認出來（出現在最多對話裡的那個；不夠明確時不猜），也可以在抓取設定手填 |
| 收件：Gmail | 要自己到 Google Cloud Console 建「電腦版應用程式」OAuth 用戶端、啟用 Gmail API，把下載的 JSON 存成 `~/.claude/session-board/gmail-credentials.json`，再按「連接 Gmail」 |
| 收件：Slack | 要自己建 Slack 機器人並填權杖 |
| 通知、點了跳到那個 session | 裝成 plugin 後自動生效，設定頁可以關。已經有自己通知腳本的人，看板的通知會保持安靜 |
| 畫面語言 | 只有繁體中文 |

資料都在使用者自己的 `~/.claude/session-board/`，每個人各一份，不會互相看到。設定（含收件的抓取設定）在 `board.db` 的 `settings` 表；Gmail 權杖是 `gmail-token.json`、看板的存取金鑰是 `token`，這兩個是檔案。**這個資料夾裡有別人寫給你的訊息全文與帳號權杖，不要整個資料夾傳給別人。**

程式裡沒有寫死任何個人路徑。從 customer-hub 帶入初始設定只在設了環境變數 `SESSION_BOARD_OLD_ENV`（指向它的 `.env`）時才做。
## 收件（Gmail、Slack、Teams）

左上角的「收件」（要先在「設定」→「收件」打開；新安裝預設關閉，關著時不抓、不判讀、左側也不顯示）。把連上的來源收到的訊息抓進來、存成一串一串，並依路由分派到資料夾。來源連上就抓（Gmail 登入過、Slack 有權杖、Teams 這台電腦有桌面版資料）；不要抓的，在「抓取設定」按它的「刪除連接」（Gmail 刪掉看板的權杖、Slack 清掉權杖、Teams 停止讀取），之後可以再連接。升級前就在用收件的安裝，總開關維持開啟。做法移植自 customer-hub（`src/gmail-poll.js`、`src/pollers/`、`src/ingest.js`、`src/routes-store.js`）；**只做到入庫與分派**，擬回覆、寄出不在這裡做。看板對三個來源都只讀不寫。

- **Gmail**：抓所有收到的信（寄件備份、草稿、垃圾信、垃圾桶、聊天紀錄除外；促銷之類的分類也抓，交給判讀去分）。標籤只用來分派，不限制抓哪些；要只抓某個標籤可在抓取設定填。**增量**：第一次往回抓設定的天數（預設 7 天），之後每次只問上次成功之後的新信（重疊一天，已有的靠訊息編號認出來），而且只有出現新訊息的討論串才會去讀全文。整串抓齊，你自己寄的只當上下文。OAuth 用戶端沿用 customer-hub 的（`~/.customer-hub/credentials.json`）；按「連接 Gmail」後看板會取得**自己的唯讀權杖**，存在 `~/.claude/session-board/gmail-token.json`，不改動 customer-hub 的 token。授權失效時頁面會明講要重新連接，不會默默顯示「沒有新信」。
- **Slack**：用機器人權杖（`xoxb-…`）抓「啟用中的 Slack 路由」所列頻道，含討論串的回覆。權杖在「抓取設定」裡填，機器人要先加入那些頻道。
- **Teams**：個人帳戶沒有 API，所以讀這台電腦上 Teams 桌面版的本機快取（`WV2Profile_tfl`）。原始檔只複製到暫存資料夾再解析，絕不以資料庫方式開啟它（會損毀）。所有對話都會抓進來，不需要路由。
- **附檔保留期限**：信件帶進對話時，附檔與信裡貼的圖下載到 `~/.claude/session-board/attachments/<討論串編號>/`。從最後一次帶入起保留「附檔保留幾天」（抓取設定，預設 30），到期整個資料夾刪除；之後再把同一封信帶進對話，會重新下載並重新起算。看板每天清一次（啟動時也清一次），收件關著也會清。舊對話裡寫到的附檔路徑在到期後會失效，要用就回收件把那封信再帶入一次。
- **加一種來源**：在 `lib/inbox/sources/` 加一個檔，照 `gmail.js` 開頭寫的格式交代它的代號、名稱、是信件還是聊天、路由比對什麼、需要哪些設定欄位、怎麼判斷已設定、怎麼抓；再到 `sources/index.js` 的清單登記。抓取設定的欄位與開關、訊息頁的卡片、路由表單都由這份描述產生，不用改別處。帶進對話時附上原信編號與附檔這一段目前只有 Gmail 有，別的信件來源要另外寫。
- **分派**：路由是「來源＋比對值 → 客戶、系統、資料夾」，比對值最長（最具體）的優先。一串訊息的狀態是 待分派 → 已分派（有資料夾）→ 已完成（你標的）；標成完成後對方再傳新訊息，會自己回到未完成。也可以在那串訊息的頁面手動分派。
- **接下去**：帶進對話的內容依來源不同。**信件（Gmail）帶整串全文**，並附上 Gmail 的討論串編號與最新來信的訊息編號，對話可以用 Gmail 連接器讀原信、直接建回覆草稿。**聊天（Teams、Slack）只帶你勾選的那幾則**：在訊息上點一下就是勾選，沒勾不能帶。兩個出口：「開新對話」在分派的資料夾開一個看板對話，內容放進輸入框（不會自動送出）；「複製」把同樣的文字放到剪貼簿，貼進已經開著的 session。要怎麼處理由你和你的其他 plugin 決定。
- **判讀：哪些是你該處理的**：每次抓取完，接著把「對方有新訊息、還沒判讀過」的訊息串交給 Claude 的小模型判讀，分成**有效**（要你做、等你回）與**無效**（知會、雜訊），並寫一行「具體要你做什麼」。每串顯示「是／不是」與幾成把握（例如「是 88%」）；有效的依把握由高到低排，低於 70% 的用虛線框標示，代表判讀自己也只是猜。訊息頁預設只列有效的；左側「收件」顯示有幾件要你處理。沒有另外的排程，跟著抓取頻率走；可在「抓取設定」關掉。
  - **交給對話或複製時（信件）**：簽名檔（結尾敬語、姓名與聯絡資訊、用分隔線框起來的名片、免責聲明）會先拿掉，引用的每一封舊信各自處理；這是照形狀判斷的，拿掉幾處會寫在開頭，資料庫裡存的與畫面上看到的仍是原文。附檔在這時才下載，存到 `~/.claude/session-board/attachments/<討論串編號>/`，路徑列在開頭讓對話直接讀；信裡直接貼的圖片（截圖）在純文字裡只剩「[影像]」這種記號，交出去時記號會換成「[圖片：存檔路徑]」，圖檔一併下載，對話可以直接讀圖；簽名檔裡的標誌隨簽名檔一起拿掉、不下載。單檔超過 25 MB 或一串超過 20 個／80 MB 的不下載並註明。訊息串上方的「資料夾」是一個屬性：點一下從用過的資料夾裡選、或選其他資料夾、或貼路徑，選了就分派。
**你是誰**：抓取設定的「你的信箱與名字」（Gmail 帳號本身自動算進去，其他信箱、名字用逗號加上）。由這些寄出或署名的內容算你自己寫的，出現在別人來信的引文裡也不會被當成你的待辦；改了之後，提到你的訊息串會重新判讀一次。成本：只送有新訊息的串。每串裡「上次判讀之後新進來的」給全文（每則最多 6,000 字），之前判讀過的只帶最後 4 則各 300 字當上下文；一次呼叫裝不下的留到下一次，每次抓取最多 5 次呼叫；不給工具、不載入 MCP 與斜線指令、不留對話紀錄。實測 33 串共 3 次呼叫、約 $0.019。
  - 安全：送去判讀的是別人寫的內容。提示裡把它標成不可信資料，模型沒有任何工具可用，回傳的內容只會變成四個固定分類之一加兩行短文字。
  - 你自己回覆不會觸發重新判讀；對方再傳新訊息才會。標成完成的不判讀。判讀拿不準時歸「知會」，不硬塞成要你做。- **多久抓一次**：預設每 15 分鐘，可在「抓取設定」改，0 表示只在按「現在抓取」時抓。
- **資料放哪**：全部在看板的資料庫（`inbox_thread`、`inbox_message`、`inbox_route`、`inbox_state`），只在這台電腦。Slack 權杖也存在那裡，不會傳給頁面。

## 沒開著的對話、隱藏、結束

- **引用**：從收件帶進對話的信或訊息不會倒進輸入框，而是以一條「引用」掛在輸入框上方（可按 × 拿掉），輸入框只放你自己的話。送出時引用的原文附在你的話後面，前後有記號並寫明「不是我寫的」；對話裡你的訊息泡泡只顯示你的話，引用收成一張卡片，點一下展開。
- **停住的 session 自動處理**：設定頁同名的一段，三個開關。看板每半分鐘看一次開著的 session：
  - **卡住時通知我**（預設開）：顯示執行中、但 10 分鐘沒有任何動靜的，跳一則通知，同一次停頓只通知一次。只通知，不中斷它。
  - **額度回來後，自動請它接著做**（預設關）：對話紀錄最後一行是 Claude Code 的「You've hit your session limit · resets 2:30pm (Asia/Taipei)」或 weekly limit 時，先通知你它停了、額度幾點回來；到那個時間再過一分鐘，請它接著做。額度回來超過 12 小時才發現的不送。
  - **被 API 的暫時性錯誤中斷時，自動再試一次**（預設關）：過載、伺服器端限流、5xx、連不上。兩分鐘後請它接著做，同一個 session 一小時最多三次。額度點數用完、要重新登入、對話太長這類等不會好的錯誤不處理。
  - 只對「開著、沒在執行、也沒在等你核可」的 session 送話，送的方式跟排程一樣（看板裡的對話直接送；終端機裡的用 session 互傳訊息）。每一次停下只處理一次，看板重啟也記得。第一次啟用時，當下已經停著的一律不動，只處理之後才發生的。最近處理了什麼列在設定頁那一段下面。
- **執行途中送訊息**：Claude 還在執行時送出的訊息會立刻交給 Claude Code，它做完手上那個動作就會讀到並照做，在同一輪裡（實測 2.1.325：三個指令跑到第一個時插話叫停，後兩個就沒有跑）。核可卡片開著時送的也一樣。看板不再自己排隊；按「停止」是停掉這一輪。對話紀錄把這種訊息記成 `queued_command`，看板會把它當成你說的話顯示，並標「執行途中送出」。
- **複製到別的地方**：在對話裡選取後複製，剪貼簿拿到的是乾淨的內容（表格只有格線與文字，粗體、連結保留，沒有看板的字型、顏色與底色），貼進 Teams、Outlook、Word 不會帶著一堆樣式。表格上滑鼠移過去有「複製表格」，一次複製整張。
- **貼圖片**：看板對話的輸入框可以 Ctrl+V 貼上截圖、把圖檔拖進來，或按「圖片」選檔。圖片以影像內容直接交給 Claude（不是存檔再給路徑），一則最多 8 張、每張 5 MB 以內，超過約 3.5 MB 或長邊超過 2400 px 的會先縮小。排隊中的訊息連圖一起排；按停止被退回的訊息只退文字，圖要重貼。圖片顯示在自己的訊息泡泡裡，按一下放大；舊訊息的圖在畫到時才向看板要（`/api/image`，從對話紀錄裡讀出那一張），不會讓整段對話變慢。
- **通知**：左側「通知」列出現在還沒處理的事（等你回應、做完了還沒看、可能卡住、額度用完、被錯誤中斷、排程要你決定、預算）。每一則存在資料庫的 `notice` 表，開著直到事情結束，由看板自己關掉並記下原因；開與關都由事件觸發，不靠定時去查。它不是 Windows 通知的紀錄，兩邊互不寫入。
- **結束看板裡的對話**：對話上方「結束對話」（按兩次）。停止它的程序並從看板拿掉；對話紀錄保留，可從「舊對話」開回來。「隱藏」只是不列在清單上，它還開著。
- **核可模式**：看板裡的對話上方有一行寫它會不會先問你（例如「改檔、跑指令前會先問你」「自動模式：多數動作不會問你」）。這是 Claude Code 自己的設定（`permissions.defaultMode`），看板沿用、不在這裡改；對話啟動後以它的程序回報的為準。
- **看一個動作實際做了什麼**：對話裡折起來的動作列，每一列都可以再展開：Bash 顯示完整指令，Write 顯示寫進檔案的內容，Edit 顯示把什麼改成什麼。展開時才向看板要（`/api/tool`），不會讓對話變慢。
- **沒送到的訊息**：在執行途中送出、Claude 還沒讀到就被停止（或程序結束、看板重開）的訊息，會在對話最下面留一張卡，可以編輯後送出、原樣再送一次，或拿掉。附的圖存在 `~/.claude/session-board/unsent/`，送出、拿掉或整個對話從看板移走就刪（一個對話最多留最近 30 則）。
- **在另一台裝置開 localhost**：透過 Tailscale 從別的裝置開看板時，對話裡的 `http://localhost:埠` 是看板那台電腦上的網站。按連結或「開啟」，看板會在它的 Tailscale 位址開同一個埠、把那個網站接過來，在新分頁打開。只有跟這台電腦同一個 Tailscale 帳號的裝置連得到（跟看板本身同一個檢查），沒按不會開，一小時沒用就關；看板自己的埠不轉。限制：網站自己的網頁、程式裡寫死的 `http://localhost:…` 不會改寫；用 https 的開發網站會以 http 開（在 Tailscale 的加密裡）。
- **Artifact**：看板裡的對話也能發布 Claude 的 Artifact（Claude Code 在這種方式執行時預設關閉，看板用 `CLAUDE_CODE_ARTIFACT=1` 打開）。發布後直接打開：在看板這台電腦說的就在這台的瀏覽器開，從另一台裝置說的就在那台開（瀏覽器擋新分頁時，畫面下方會有一顆「打開 Artifact」）。同一頁之後更新不再重開。你自己關掉 Artifact 的設定照樣有效。
- **harness 流程圖**：辦公室房間的 harness 面板有「看流程圖」（`.claude/harness/flow.html`，沒有 archify 時是 `flow.md`）；圖是 harness 自己在安裝和健檢的最後一步畫的，看板只負責看。
- **左欄順序**：戰情室、辦公室、合作、排程、收件、設定可以拖右邊的六點把手換位置，或選到後按 Alt+↑／Alt+↓。
- **每天上班統整**：LINE 接通、收件打開時，收件頁最上面有開關。預設週一到週五 09:30，用 LINE 告訴你今天要做什麼、還有什麼沒做、哪些對話在等你；時間在排程頁改（它是一筆排程）。送之前先抓一次收件，再核對：Gmail 每一串在對方最後一封之後你有沒有寄信（這是查到的事實），加上你寄出的信、各專案的對話與你自己的 git commit，交給 Claude 判斷做完了沒（這是判讀，訊息裡會寫「看起來」和依據）。只列不改：不會自動標完成。Teams、Slack 的訊息串沒有「有沒有回」可以查寄件備份，只靠收件裡看得到的和上面那些線索。
- **排隊訊息的收回**：排隊的訊息送出後十秒內，原位會留一列「剛送出」與「收回」。收回會停止那一輪並把文字放回輸入框（那一句已經送給 Claude，紀錄裡仍看得到）。
- **舊對話怎麼找**：可以依資料夾或依時間列出，並只看今天／昨天／本週／上週／更早。在暫存資料夾（Temp）跑的對話平常收起來；搜尋時一樣找得到。搜尋找整個對話：標題、資料夾、你說的、Claude 說的、Claude 下過的指令與動過的檔名（不含指令印出來的內容），不限日期，隱藏的也找得到。
- **排程**：左側「排程」。每筆設定什麼時候（一次、每天、每週幾、每隔幾小時）、在哪裡做（資料夾開新對話，或接續某個 session）、做什麼。看板每 20 秒檢查一次，到點後 3 分鐘內算準時；超過（看板沒在跑、電腦關機）就記成錯過並發通知，由你按「補跑」或「略過」，不會自己補跑。同一個時間點只會執行一次，看板重啟也一樣。接續的 session 開在終端機裡時，看板會起一個沒有視窗的小程序，用 Claude Code 自己的 session 互傳訊息功能把話送過去；雙方權限模式不同時對方會把訊息扣住等你核可，這時依那筆排程的設定處理（只通知、開分身在看板跑、搬到看板跑）。「執行時不問核可」預設關閉，逐筆設定。
- **辦公室**：左側「辦公室」。每個資料夾一間、每個 session 一張桌子，依等你批准、可能卡住（執行中但對話紀錄十分鐘沒有新內容，只是提示）、進行中、做完了、閒置上色與篩選。
- **還沒開始的對話**：按「＋」或從收件帶信開出來、但還沒送出第一則訊息的對話，不是 session：不列在左側清單、不算進數量，只有你正在打字的那個畫面看得到它。沒送出就離開會關掉（打了字沒送出的也一樣）；沒有頁面開著它的，看板在兩分鐘後自動移除。
- **沒開著的對話**：左上的「舊對話」（首頁也有同一份清單）列出最近 30 天、現在沒開著的對話（新的在上，先顯示 40 個），每個可以「終端機」（開視窗接續，用該資料夾上次的啟動參數）或「看板」（搬進看板接續）。搜尋框找整個對話：標題、資料夾、你說的、Claude 說的、Claude 下過的指令與動過的檔名（不含指令印出來的內容）。
- **清單第三行**：左側每個 session 的名字與狀態下面，多一行「你：…」，是你在那個 session 最後說的話。看板替你開的（排程、自動健檢、LINE 小秘書）有紫色標籤，滑鼠移上去看是哪一筆；終端機、背景的也有標籤。
- **隱藏**：對話上方的「隱藏」把它從左側清單拿掉，session 照常執行；清單最下面可以再顯示。沒開著的對話也可以隱藏。
- **結束**：終端機 session 的對話上方有「結束」，要按兩次。它會先確認那個程序此刻確實登記在這個 session 名下，分不出來就什麼都不結束；結束後試著關掉它的視窗（只在找到唯一一個符合的視窗時），並把它記成「你關掉的」。

## 左欄、改名、辦公室的排列、只看你開的

- **收起左欄**：左欄頂端的「«」或 Ctrl+B。收起後剩一條細邊，有「»」展開鈕和等你回應的數字。看板會記住，下次打開還是收起的。
- **改名**：對話上方名字旁的「✎」，或在左欄的項目上按右鍵。看板把你取的名字記在自己的資料庫，排在所有標題之前，所以不會被 cc-statusline 每次送訊息後改寫的摘要蓋掉。清空名字就回到自動的標題。看板裡的對話改名時也會送一次 `/rename`，讓 Claude Code 自己也知道（有合作代號的不送：其他成員靠代號找它）；終端機裡的 session 只改看板這邊。
- **辦公室的我的最愛與順序**：房間名字前的「☆」標成最愛，排在最上面一區；房間可以拖曳調整順序（最愛區、其他區各自排）。沒排過的照原本的規則排在後面。設定頁可以讓其他房間收成一列。
- **只看你開的 session**：設定頁「自動隱藏」的「隱藏其他程式開的 session」。Claude Code 在每個 session 記著它是怎麼開的（`entrypoint`）：終端機視窗是 `cli`，程式用 `claude -p` 或 SDK 開的不是。看板自己的對話也是用 `claude -p` 跑的，所以另外認得：從 0.4.0 起看板記住自己開過的每一個（更早而且沒開著的，看第一則訊息的形式）。沒記怎麼開的，看第一句是不是程式送的、有沒有視窗。預設開。判斷不出來的，可以把資料夾加進「一律不列出的資料夾」。被藏起來的，清單最下面仍可以點開來看。

## 小模型判斷（decide）

設定頁「小模型判斷」選的模型（`decideModel`）用在三處：「下一步」要不要出現「交給 goal2 做完」、收件的判讀、推薦的外部 plugin 從網址讀出名稱和說明。

「下一步」是把那一輪最後一則回覆交給小模型回答一題（只回機率與那幾件事，不寫字）。題目是資料：`questions/unfinished.json`（題目、判準、正反例、輸出形式、門檻）。要改題目，放一份同名檔到 `~/.claude/session-board/questions/`。判斷器 `lib/decide.js` 不依賴看板的其他程式，也可以單獨用：

```
node lib/decide.js --question unfinished < 一段文字
node lib/decide.js --question 路徑/我的題目.json --model haiku < 一段文字
```

看板上的 `POST /api/decide { question: <題目 id>, text }` 也是同一個判斷器（只收題目 id，不收路徑）。同一題對同一段文字只問一次；失敗的十分鐘後才再問。

## 合作（幾個 session 一起完成一個目標）

左欄「合作」，或對話上方「＋ 合作」。勾 2 個以上的 session（看板對話或終端機 session），寫共同目標、每位的角色和負責什麼。看板會：

- **建一份共用帳本** `<成員的資料夾>/.claude/collab/<編號>.md`：目標、成員與分工、介面清單（每位成員一欄，跟上了打 ✓）、承諾清單（`- [ ] [角色] …`）、待你裁定、使用者裁定（原話）、驗證紀錄、合作規則。所有成員共用這一份。
- **給每位一個固定代號**（預設 `S<流水號>-<短名>`），其他成員用它 SendMessage。代號跟著 session：標題、摘要怎麼變、程序重開、加入別的合作，代號都一樣。看板對話每次啟動都帶 `--name <代號>`（2.1.331 實測：中途改標題、接續都不會變）；看板開回終端機的也會帶。終端機 session 自己開的看板改不了（跨 session 訊息裡的斜線指令不會執行），合作頁會給一行 `/rename …` 讓你貼到它的視窗。
- **讓權限模式一致**：成員的模式不同時，收到訊息的一方會把它扣住等它的使用者核可；看板對話沒有人能核可，訊息就永遠送不到（實測：auto 被扣住、bypass 立刻收到）。所以看板對話加入時預設改成 bypass（`collabBypass`，可在表單取消）；終端機 session 的模式看板改不了，不一致時合作頁會警告。
- **送一份合作說明**給每位：目標、它的角色、其他成員的名字和資料夾、帳本在哪、怎麼聯絡、合作規則（每個介面都要跟對方確認、改了介面要更新帳本並通知對方、答應的事寫進承諾清單、不能替使用者決定、宣稱完成前要聯合驗證逐欄比對、附檔案:行號）。
- **名字變了不打擾**：成員登記的名字跟代號不同時（例如終端機 session 重開），看板只在帳本的成員節註明現在的名字，不送訊息給其他成員。
- **讓成員找得到**：合作進行中、24 小時內有成員（終端機的也算）做過事時（`collab/config.json` 的 `keepHours`，0＝不留），看板不會因為閒置 15 分鐘結束成員的程序；看板重開或程序不見了，會叫回來（最慢約五分鐘；只開程序、不送訊息，不花 token）。閒著超過 6 小時的會換一個新程序，才不會一直用舊版的 Claude Code 和外掛。
- **換編號也跟得上**：編輯重送、`/clear` 會讓對話換成新的 session 編號，代號、成員身分、帳本、排程和你取的名字都跟著移過去。

合作頁列出：成員（忙／閒、現在的名字、權限模式）、帳本裡還沒勾的承諾、某位成員還沒跟上的介面（紅字）、要你裁定的題目（在這裡回答，看板把原話寫進帳本並送給每一位）、成員之間的訊息（從它們的對話紀錄讀 SendMessage 送出的和收到的，送出的標「對方收到」）、帳本全文。「結束合作」只是標成已結束，不動任何 session、不刪帳本。

規則文字、帳本與說明的範本、帳本的節名都在 plugin 的 `collab/`（`config.json`、`ledger.md`、`brief.md`、`rules.md`、`decision.md`）；要改，放一份同名檔到 `~/.claude/session-board/collab/`（`config.json` 只要寫你要改的欄位）。

## CLAUDE.md 面板

辦公室每個房間的「CLAUDE.md」，和頂端工具列的「全域 CLAUDE.md」：看 Claude Code 在那個資料夾會載入哪些指令檔、各有多長、有什麼問題，需要時請 Claude 評估或微調。

- **列哪些**：照 Claude Code 官方文件（code.claude.com/docs/en/memory）的載入規則與順序——組織管理的那份（有才列，唯讀）、`~/.claude/CLAUDE.md` 與 `~/.claude/rules/`、上層資料夾的 `CLAUDE.md`／`CLAUDE.local.md`、專案的 `CLAUDE.md`、`.claude/CLAUDE.md`、`.claude/rules/`、`CLAUDE.local.md`、用 `@` 引用的檔（最多四層）；沒有任何 CLAUDE.md 的資料夾列 `AGENTS.md`。子資料夾的 CLAUDE.md 是 Claude 進去工作才載入，不列。「全域 CLAUDE.md」只列每個專案都會載入的。
- **每一份**：行數、估算的 tokens（中文約一字一個、英文約四個字母一個）、git 狀態、看板自己做的檢查（太長、壞掉的引用、寫在行內反引號裡卻找不到的路徑或指令、重複的句子、疑似金鑰或個資——金鑰只說第幾行，不顯示內容）。展開看內容（目錄收在上面，按了跳到那一段）；內容提到的檔案可以點開預覽，標題列有回來的按鈕。
- **綜合評估**：按了才跑（`claude -p`，只讀不改，不載入你的設定與 hook，約 1 到 3 分鐘）。全域那個另外比對各專案的 CLAUDE.md。
- **微調**：在內容上框選一段文字，下面就出現輸入框，寫一句要怎麼改（也可以「微調整份」，或在下面追問裡說要改哪裡）。Claude 只改框選的地方，擬好後在那裡顯示差異，按「套用」才寫入；寫入前備份到 `~/.claude/session-board/claudemd-bak/`，可以「復原」上一次。提案之後檔案被改過就不能套用；全域與上層資料夾那份套用前要再確認一次。改完的檔在 git 裡時記得 commit。

## 外掛分析與找外掛

辦公室每個房間的「外掛分析」：照 plugin-manager 的 setup-plugins，讀那個資料夾的 CLAUDE.md、README 和檔案類型，從你的 plugin 庫、profile 和推薦清單（plugin-manager 的 `recommends.json`）挑適合的，也列出已經裝的、可以考慮拿掉的。分析只讀不改，約 1 到 3 分鐘；勾選後按「套用」才裝，一律裝在那個資料夾（marketplace 型用 `claude plugin install --scope project`，skill 合集型只抓那個 skill 的資料夾，複製到 `.claude/skills/`）。下面可以追問，回答可能改上面的清單。

**找外掛**：在追問裡許願（「我想要一個做簡報的 skill」），Claude 照 [skill-fetch](https://github.com/girofu/skill-fetch) 的方法到 SkillsMP、GitHub、skills.sh 等 skill 庫找、評分；找到、而且有 GitHub 資料夾網址的，列進清單讓你勾選套用。實測一次約半分鐘、約 0.2 美元。

- **已經有 skill-fetch 的不會問**：裝在 ~/.claude/skills 的，每個資料夾都直接啟用；只裝在某個專案的，那個專案直接啟用（搜尋時用它自己的），其他專案仍會問。你按過「啟用」或「關閉」的照你選的。
- **沒有 skill-fetch 的，第一次會問要不要啟用**。啟用會把 skill-fetch 裝到全域（`~/.claude/skills/skill-fetch`），並請你填 SkillsMP、SkillHub、Skills Directory 的金鑰。金鑰只填一次，每一個都可以不填；存在 skill-fetch 讀的 `~/.claude/skills/.fetch-config.json`，畫面上只顯示有沒有填。選「先不要」，許願就只會在既有的清單裡找。
- **搜尋時的限制**：在一個空的暫存資料夾裡跑 `claude -p`，不載入你的設定與 hook，只放行 skill-fetch 會做的事：指令只有 `gh search`、讀 anthropics/skills 清單的那一條 `gh api`、它的 npx 查詢工具和它的兩支 skill 庫腳本；網頁只有 skills.sh、skillsmp.com 和 GitHub；讀檔只有 skill-fetch 自己的檔和專案的 CLAUDE.md、README.md。其他指令、網址、檔案一律被擋（2026-11-22 實測：讀金鑰檔、`cat`、串接指令都被拒）。金鑰它讀不到：skill 庫的腳本自己讀設定檔（skill-fetch 的 SKILL.md 寫明它的兩支腳本從 `~/.claude/skills/.fetch-config.json` 讀金鑰），SkillsMP 的工具只在這次搜尋臨時提供，金鑰放在它讀不到的另一個暫存資料夾、跑完就刪（看板中途被關掉留下的，下次啟動時刪掉距離那次搜尋超過 15 分鐘的）。你自己註冊的 MCP 不會被動到。找到的每一個都先向 GitHub 確認資料夾裡真的有 SKILL.md 才列出（連不上 GitHub 的會另外說明）。同一個資料夾一次找一個願望，其他的排隊（最多排三個，再多的會在回答裡說明沒有去找）；找的途中看板重新啟動，那個願望會在對話裡註明「還沒找完」，不會自己再找一次（再找要花用量），找到但還沒寫進分析的結果則會留著寫進去。搜尋用的指令由 Claude Code 的 Bash 工具執行；Windows 上它需要 Git Bash，沒有的話這些指令跑不了（這是 Claude Code 的行為，看板不另外處理，也不會因此放寬），只剩網頁與 SkillsMP 可查，找到的會比較少。
- **加入推薦清單**：用過覺得好，在追問裡說要加進推薦清單，Claude 會擬好那一筆（名稱、來源、說明、標籤），面板出現「加入推薦清單」按鈕，按了才透過 plugin-manager 的 `register-external.js` 寫入。要讓別台電腦也看到，再執行 `/plugin-manager-publish`。

## 關機後把 session 開回來（常駐）

- **預設**：每個開著的終端機 session 都是「常駐」。看板每 10 秒記一次現在開著哪些（存在 `~/.claude/session-board/keep.json`），連同它當初的啟動指令。
- **你自己關掉的就不常駐**：兩個訊號。一是 Claude Code 的 SessionEnd hook（`scripts/session-end-hook.js`）：你用 `/exit` 之類的方式結束 session 時它會記一筆到 `~/.claude/session-board/ended/`，看板沒在跑時也記得到。二是 session 不見之後看板還繼續活了 90 秒以上（直接關視窗、程序被結束時 hook 不會跑，靠這條）。兩者任一成立都算你關的，移到首頁的「你最近關掉的」（保留 14 天，可按「重新開啟」）。session 和看板差不多同時消失（關機、重開機、當機），算被中斷的，保持常駐。
- **重開之後**：看板首頁列出「上次看板停止時還開著的終端機 session」，勾選後按「還原」，各開回一個終端機視窗（用原本的啟動參數加上 `--resume`），或按「不用了」移出清單。還原的意思是回到原本的樣子：原本是終端機視窗的就回到終端機視窗；看板裡的對話不在這份清單裡，它本來就會留在看板上，不需要還原。
- **個別開關**：終端機 session 的對話上方有「常駐：開／關」。
- **全自動**：設定頁有兩個開關，預設都關。「登入 Windows 時自動啟動看板」會在你的「啟動」資料夾放一個 `session-board.vbs`（關掉就是刪掉它）；「看板啟動時自動把常駐的 session 開回終端機」則不問直接開。兩個都開，重開機後才會全部自己回來。
- **限制**：開回來的是對話，不是當時的動作，做到一半的回合、背景工作、子代理不會自己接續。背景執行的 session、以及只是在看背景工作的視窗不在常駐範圍。看板沒在跑的期間你關掉的 session，看板分不出來，下次啟動仍會列出（按「不用了」即可）。

已經開著的分頁不用手動重新整理：頁面發現看板的頁面檔換過了會自己重新載入，並回到原本的位置（哪個對話、戰情室或設定，記在網址的 `#` 後面）。如果你有卡片還沒回覆、有填到一半的欄位，或有只留在這一頁的東西（還沒送出的附件、存不進看板的暫存、收件引用；打在對話框裡的字會先存成草稿），它不會自動重載，改在左下角顯示「看板有新版，按這裡重新整理」。**停止看板會一併結束看板裡正在執行的對話程序**（對話本身不會消失，下次送訊息會接續）。

## 設定檔

在看板左上角按「設定」就能改，存檔後馬上生效。設定存在看板的資料庫，改了不用重啟看板。在頁面上填錯（不是完整路徑、資料夾不存在）會當場告訴你原因、不會存進去。

```json
{
  "pickerStartDir": "C:\\Users\\你\\Projects"
}
```

| 設定 | 作用 | 沒設時 |
|---|---|---|
| `pickerStartDir` | 開新對話按「選擇資料夾…」時，那個視窗一開始停在哪個資料夾 | 由 Windows 決定（通常是上次用這個視窗的位置） |
| `sidebarCollapsed` | 左欄收起來（只剩一條細邊） | `false` |
| `sidebarShortcut` | Ctrl+B 收起／展開左欄 | `true` |
| `officeFavorites` | 辦公室標了星的房間（資料夾完整路徑的清單），排在最上面 | `[]` |
| `officeOrder` | 辦公室房間拖曳後的順序（資料夾完整路徑的清單） | `[]`（照誰在等你、最近說話排） |
| `officeCollapseOthers` | 有標星的房間時，其他房間收成一列 | `false` |
| `hideProgramSessions` | 不列出其他程式開的 session（見下） | `true` |
| `hideProgramFolders` | 這些資料夾裡的 session 一律不列出：資料夾的名字（任何叫這個名字的資料夾）或完整路徑（家目錄可寫 `~`） | `[]` |
| `decideModel` | 小模型判斷（下一步、收件判讀、推薦的外部 plugin）用哪個模型（`haiku`、`sonnet`、`opus`） | `haiku` |
| `collabNamePattern` | 合作成員的代號（`{id}` 流水號、`{short}` 成員短名；空白與引號等符號會換成 `-`） | 空＝用 `collab/config.json` 的 `S{id}-{short}` |
| `collabBypass` | 看板對話加入合作時改成 bypass（表單上的預設勾選） | `true` |

這幾項都在設定頁有開關或欄位（星號、拖曳、左欄的 « » 也是改這幾項），存在看板的資料庫。

路徑裡的反斜線要寫兩個（JSON 的規則）。值的型別不對、或資料夾不存在時，該項設定當作沒設，不會報錯。

## 組成

單一 Node 程序，沒有相依套件、不用建置。資料存在 Node 內建的 SQLite（`~/.claude/session-board/board.db`），不需要另外裝資料庫。

|------|--------|
| `server.js` | HTTP 伺服器，只聽 127.0.0.1 |
| `lib/sessions.js` | 把各資料來源彙整成 session 清單（唯讀） |

| `lib/monthly.js`、`scripts/usage-scan.js` | 每月用量與 API 等值費用（從 cc-statusline 的用量紀錄匯總，在獨立程序裡跑） |

資料庫用 Node 內建的 SQLite（`node:sqlite`，需要 Node 22.5 以上），不用另外安裝套件。它放在使用者資料夾而不是 plugin 資料夾：安裝後的 plugin 位於 `~/.claude/plugins/cache/…/<版本>/`，每次更新都是新資料夾，資料庫放那裡會在更新後歸零。舊版留下的 `config.json` 與 `usage/*.json` 第一次啟動時會自動匯入（`config.json` 改名為 `config.json.imported`）。

## 看板裡的對話怎麼運作

每個對話是一個 `claude -p --input-format stream-json --output-format stream-json` 程序。訊息從標準輸入送進去，事件從標準輸出出來，同一個程序可以連續對話多輪。Claude 需要核准時會送出一個請求並等待回覆，看板把它變成頁面上的「允許／拒絕」。

- 回覆是逐字顯示的：程序以 `--include-partial-messages` 啟動，文字一小塊一小塊送到頁面；寫的過程顯示純文字，整段寫完才排版成表格、粗體等格式。子代理自己的輸出不會混進來。終端機 session 做不到逐字，因為看板只能讀它寫進檔案的內容，每 3 秒讀一次。
- **背景工作與子代理**：一輪講完之後，它啟動的子代理或背景指令可能還在跑，做完時 Claude Code 會自己再開一輪回報，不用你說話。這段期間看板顯示「背景工作中，做完會自己回報」而不是「待命」，對話下方列出每一項（子代理的種類、說明、正在用哪個工具、已跑多久），也可以繼續打字。
- **提問表單**：Claude 用選擇題問你時（AskUserQuestion），頁面出現表單，單選、複選、自己寫都可以，送出後它照你的回答繼續。
- 程序在送出第一則訊息時才啟動，15 分鐘沒有新訊息就結束以釋放記憶體；下一則訊息會用 `--resume` 接續。有背景工作在跑時不會被結束。
- **停止看板會結束它執行的所有對話程序**，連同進行中的回合與背景工作。所以只要有對話正在執行、等你回答或有背景工作，`start.js --stop` 會拒絕並列出是哪幾個；確定要停就加 `--force`。
- 權限模式沿用你的 Claude Code 設定，看板不另外指定。
- 專案的 CLAUDE.md、hooks、plugin 照常載入。

## 資料從哪來

| 來源 | 拿什麼 | 備註 |
|------|--------|------|
| `~/.claude/sessions/*.json` | 哪些終端機 session 活著、狀態、資料夾 | **不是官方公開介面**，Claude Code 改版可能變。每個欄位都當成可能不存在來處理 |
| `~/.claude/cc-statusline/state/claude-summary-*.txt` | 摘要標題 | cc-statusline 寫的，約第 10 則訊息後才有 |
| `~/.claude/projects/<資料夾>/<session>.jsonl` | 對話內容、沒有摘要時的標題 | **只從尾端往回讀**，讀到夠用就停，有上限。這類檔可達數百 MB，整檔讀取會把記憶體吃光 |

## 限制

- **支援 Windows 加 Windows Terminal，以及 macOS 的 Terminal**（Mac 的差異見「安裝在 Mac 上」）。
- **終端機 session 在看板上不能打字**。能替你把話送進一個正在終端機裡跑的互動式 session 的官方管道只有 Remote Control；要在看板打字就得把它搬過來。
- **「移到終端機」之後，看板可能認不出那個 session**。實測（2026-11-12）終端機視窗有開、對話也接上了，但 Claude Code 沒有為它寫出登記檔，所以它不會出現在清單上，也就不能再從看板搬回來。原因還沒查清楚。
- **新資料夾第一次移到終端機時**，Claude Code 會先問「是否信任這個資料夾」，要在那個視窗裡回答。
- **對話先顯示最近約 120 則**，往上捲到頂會自動載入更早的（最多 3000 則）。
- **切視窗靠比對視窗標題**：兩個視窗標題完全相同、或開頭 20 個字相同又分不出長短時不會切換；一個視窗開多個分頁時只有目前分頁切得到；當下最前面是遠端桌面時 Windows 可能不讓切。
- **判斷終端機 session 是否活著只看程序編號還在不在**，程序編號被別的程式重用時會出現假的一筆。
- **由別的程式用 `claude -p` 驅動的 session**（例如排程工具起的）預設不列；關掉隱藏時會列出來並標「背景」，只能看，不能切視窗也不能搬。

## 存取限制

看板能啟動與結束程序，所以做了三道限制：只聽 127.0.0.1；除了存活檢查以外的 API 都要帶金鑰；請求的 Host 標頭必須是看板自己的位址。

這是用來擋「瀏覽器裡其他網頁偷偷呼叫本機服務」，不是沙箱：同一個使用者帳號下的其他程式讀得到金鑰檔。

「搬到這裡對話」會結束一個程序。看板只結束登記檔裡登記給那個 session 的程序編號，結束前會重讀登記檔確認；確認程序真的結束後才在看板這邊接續，否則不接手。
