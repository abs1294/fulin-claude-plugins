# deliver-report

把本次的**交付產出**寫成一段口語、務實的**交付訊息**——固定 fulin 慣用的語氣，形狀依當次情境而定。

## 解決的痛

每次要把一批檔案（分析報告 + 明細 + 原始資料 + 實作/設定檔）交給收件人時，都要手寫一段導讀訊息。語氣有既定偏好，但每次重寫很煩、還容易漏掉版本一致性檢查。更常見的失敗是**寫太長**——把報告摘要一遍，收件人不看。

## 觸發

說「寫交付訊息」、「交付這批檔案」、「產出交付信」、「幫我寫給客戶/工程端的說明」、「整理成交付訊息」、「回覆對方的提問並附報告」、「回覆會議留的待決事項」、「deliver」、「handoff」即觸發。

## 怎麼運作：動筆前先定四件事

**沒有「型」可選**（0.3.0 拆掉了舊的三型選型表）。四件事各自獨立決定、可自由組合，形狀自然長出來：

1. **檔案是主體還是佐證** — 對方要的是「這批成果本身」（逐檔清單放開頭、可展開），還是「答案」（附件退到結尾、一句話帶過）？
2. **有沒有對方的問題要回** — 有的話骨架就長成那組問題的形狀。來源不限來信提問：會議待決事項、反覆追問的疑慮、驗收檢核項都算。反方向（你有問題要問對方、他不回就沒法繼續）獨立一區。
3. **單一收件人還是多類分眾** — 判準是「不同人是否只讀不同子集」，不是檔案數量。
4. **內文密度** — 每句都要過「這句不寫，對方會不會做錯事、或對現況產生錯誤認知」。

定完之後才看範例——**範例是抄語氣與用詞密度的，不是抄結構的**。

## 三種常見形狀（是產物，不是模板）

| 形狀 | 決定組合 |
|------|----------|
| 逐檔導讀 | 檔案主體 + 無提問 + 單受眾 |
| 分眾（`▌` 按對象切區塊） | 檔案主體 + 無提問 + 多類分眾 |
| 逐題回覆 | 檔案佐證 + 有提問 + 高壓縮 |

組合跟哪個都不同時，照四個決定自己長，別硬套。

## 特點

- **語氣固定，形狀依情境而定**：這是使用者要固定的核心。
- **技術詞翻人話**：專有名詞只保留在「給工程端那一檔」的說明裡，其餘白話。
- **收件人沒指定就寫 `Hi，`**：**絕不留 `<收件人>` 這類佔位符**（忘了改會很難看）。
- **誠實邊界有硬規則**：依「對方不知道會不會有人受損」決定進信或只留指路；**凡安全性失效一律進信**，不因「是我方施作紀律」而降級。
- **不擅自改寫對方的問題**：前提客觀失效才校正；只是「我認為他該問別的」一律照答再建議。
- **寫前順手整理**：列實際檔案、檢查版本一致性、依邏輯排序（彙總→明細→原始資料→實作/設定），但不擅自改檔。

前置依賴：無。
