# 收斂準則

> 知道何時該停——攻夠了沒。

## 收斂前置：面向覆蓋閘

任何準則宣告收斂前，必須先過**覆蓋閘**：SKILL.md 第一步**使用者核可的每個面向**都**至少被認真攻過一輪**（steel-manned，非一句帶過）。記一份 covered 面向 checklist（面向名 → 已攻/未攻 + 該輪最強攻擊摘要）。存在未攻面向時不得宣告收斂，須先補攻——否則退化成只攻淺面向就 GO 的「確認劇場」。

## 核心收斂條件：迴圈到攻不破（唯一輪 0 新即停）

**兩模式共用、預設行為**：紅攻 → 藍守 →（修）→ 再跑一輪……**直到某一輪紅方產生 0 個新的真弱點**就收斂。

- 「新的真弱點」= 藍方驗證為真（非假陽性）+ 去重後非變體。
- **一輪 0 新即停**（不需連續多輪確認）——前提是已過下方「面向覆蓋閘」（確保不是只攻淺面向就 0 新）。
- **修復複驗前置**：宣告收斂前，歷輪「宣稱已修」的 finding 必須**全數通過修復複驗**（實讀改後檔案驗落地 + 原攻擊路徑再打一次；見 SKILL 第四步）。「修了」只認驗過的產出、不認修方自述——存在複驗不過項 → 不得收斂，退回重修。
- **硬上限**：迴圈受 round 上限保護（預設 5 輪），達上限即強制停並回報殘餘弱點，避免極端情況攻不完。

### 可調參數（覆寫核心行為時用）

| 參數 | 作用 | 預設 |
|------|------|------|
| `round_cap` | 迴圈硬上限輪數 | 5（可 1-10） |
| `dry_rounds` | 要連續幾輪 0 新才停（提高嚴謹度用） | 1（即唯一輪 0 新即停） |
| `all_addressed` | 額外要求：每個 CRITICAL/HIGH 須 REFUTE/HARDEN/MITIGATE，或 ACCEPT 且明列殘餘風險才停（高風險決策用） | 關 |

> `all_addressed` 不要求「零 ACCEPT」——真實且不可消除的殘餘風險，只要明列在 go/no-go 即視為 addressed，允許收斂並標「帶風險上路」。否則高風險決策（最常有不可消除殘餘風險）會死鎖。

## 「新攻擊」怎麼算（去重）

每輪數新攻擊前，先剔除重複/變體：

- **兩份清單，用途不同**：給紅方的「已提過的顧慮」清單含所有提過的（含已被藍方剔除的假陽性）——讓紅方別一直重刷同一件事；**計數用的去重只對「已確認的」比**。假陽性就算被重刷，藍方再判一次假就被閘1擋掉，不會讓迴圈不收斂；反過來，先前判假/LOW 的顧慮若這次被藍方驗為真且 ≥MEDIUM，就是真弱點，照算（見下方「升格」）。
- **只看底層顧慮（root concern）**：與嚴重度/措辭無關。
- **重複**：跟前面攻擊一模一樣。
- **變體**：同一個底層顧慮換個說法、或範圍稍微放大。例：「團隊缺 K8s 經驗」vs「團隊缺分散式系統經驗」→ 同顧慮、變體，**不算新**。可操作判準（heuristic）：兩攻擊的修法是否相同 → 相同則視為同顧慮。
- **真新**：針對「明顯不同的弱點」，才算新攻擊。

只有「真新」的弱點（含升格的）才讓迴圈繼續下一輪；一輪內全是已確認項的重複/變體、假陽性、LOW = 0 新 = 該輪收斂。

## 機械閘：讓「要不要再跑一輪」由資料判定，不靠模型自律

> **這三道是收斂能不能擋住「紅方鑽牛角尖硬抓錯誤、硬湊 LOW 讓迴圈不停」的關鍵。** 它們是**機械判定**（照 finding 的欄位值機械過濾），不是散文勸導——對話內手動跑時逐 finding 照表執行，接 Workflow 時由 `loop-runner.md` 的腳本控制流強制。三道全過濾完，才數「本輪新真弱點」。

| # | 閘 | 規則（機械） | 擋掉什麼 |
|---|----|------------|---------|
| 1 | **真偽閘** | 藍方 `is_real:false` 的 finding → **直接丟棄，不進任何計數** | 紅方的假陽性（false finding），不讓它充數 |
| 2 | **嚴重度閘** | `corrected_severity < MEDIUM`（含 LOW）→ **不計入「新弱點」**，迴圈視同該項不存在 | 「為了續圈硬找 LOW 級雞毛蒜皮」——湊 LOW 不會讓 dry 歸零 |
| 3 | **去重閘** | 對「**已確認過的** root concern」比 → 已確認項的變體/重複不算新；先前判假/LOW、本輪被藍方驗為真且 ≥MEDIUM 的 → **升格為新真弱點** | 已確認的弱點換個說法重刷一輪、騙過收斂（假 finding 重刷由閘1擋） |

> **閘3 豁免（修復複驗不過，MANDATORY）**：某 root_concern 對應的修復若**複驗不過**（宣稱修了、實讀改後檔案發現沒落地或原攻擊仍打得穿），該 root_concern **必須從已確認集合（與給紅方的已提過清單）移除**——下一輪紅方重提**照計新弱點**，不受去重閘吞掉。去重閘只保護「已確認且複驗修好」的項，**不保護「宣稱修了」**；不做此豁免，「沒修好」會被當變體吞掉、永遠隱形，收斂形同虛設。
>
> **升格（取代舊版的「去重吞掉＋留痕」）**：某 root_concern 先前被判假或 LOW，本輪藍方驗為真且 ≥MEDIUM → 照計為新真弱點、進確認清單、要修。舊版會把它當變體吞掉、只在報告裡留痕，結果真弱點被假收斂帶過、甚至判 GO。升格不會造成迴圈不收斂：一個 root_concern 一旦確認，之後再提都算已確認項的重複；被重刷的假 finding 每次都由閘1擋下。root_concern 命名仍要具體（「哪個檔的哪個具體顧慮」），避免不同問題撞同字串被當成重複。

**計數公式（本輪新真弱點數）**：

```
新真弱點 = findings
  .filter(f => f.verdict.is_real === true)              // 閘1：真偽
  .filter(f => sev(f) >= MEDIUM)                         // 閘2：嚴重度（sev 取 corrected_severity，無則 fallback 紅方 severity）
  .filter(f => !confirmedConcerns.has(rootConcern(f))) // 閘3：只對已確認的去重（先前判假/LOW、本輪驗真的照算＝升格）
  .length
// 本數 === 0（且覆蓋閘已過）→ 該輪 dry，收斂
```

> 三道閘合起來的效果：**紅方再怎麼想讓迴圈繼續，能讓 `dry` 歸零的唯一方法是提出「藍驗為真、≥MEDIUM、且尚未確認過」的弱點**——也就是真的還有真問題。湊假的、湊小的、換皮的，全被閘擋在計數外。
>
> **兩種保證等級（別混淆）**：接 Workflow 跑時，上面的 filter 是**真的 JS 程式在算**（機械運算，模型繞不過）。對話內跑時，`is_real`/`corrected_severity` 由模型自填，這三道閘是模型「按規則自我裁決」——是**自律強化版**，非硬保證。對話內模式請把上面的 filter 當「必須誠實套用的自我檢查」，而非「有外部程式幫你擋」。

## 迴圈跑法

- 跑一輪紅藍（→ 實作模式立即修；分析模式首輪停給確認清單，確認後修）→ 有新確認弱點 → 再跑下一輪
- 某輪 0 新真弱點（且覆蓋閘已過）→ 收斂
- 達 `round_cap`（預設 5）→ 強制停並回報殘餘弱點
- 提高嚴謹度可設 `dry_rounds > 1`（需連續多輪 0 新才停）

## 收斂後輸出 go/no-go

- **攻擊覆蓋**：對第一步核可的面向逐項標三態——「已攻+驗證無弱點」/「已攻+有 finding」/「未攻到」。
- 所有 CRITICAL/HIGH 都 REFUTE（證實是假）/HARDEN/MITIGATE → **GO**
- 還有未解的 CRITICAL/HIGH → **BLOCK**
- 因任一 agent 回 null（quota/API 終止）而中途停下 → **BLOCK（中斷）**，不論已完成的部分多乾淨；補跑完才能重判
- 有 ≥MEDIUM 的 finding 藍方沒驗到（藍方回 null，Workflow 記為 `unverified`）→ **BLOCK（未驗證）**；藍方回 null 屬 quota/API 終止，loop-runner 會當輪熔斷停跑（`stoppedBy: halted_on_null`），先回報使用者，恢復後續跑補驗
- 不屬任何核可面向的 finding 列「範圍外觀察」，不影響 GO/BLOCK。
- 任一核可面向落在「未攻到」→ **BLOCK（覆蓋不全，N 個面向未攻：…）**，補攻後才能改判 GO（核可面向在提案時都已說明為何承重，故無「不承重可略過」的例外）。
- ACCEPT 的殘餘風險要明列，讓使用者知道「帶著什麼風險上路」。
