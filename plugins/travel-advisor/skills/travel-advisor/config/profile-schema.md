# 設定層格式（第①層）

本檔定義**設定檔的欄位**。規範層（`SKILL.md`、`references/`）不得出現任何數值，
一律引用本檔的欄位名。

---

## 判準：什麼東西屬於哪一層

```
Q1 改變時是因為「換一趟行程／換一個人」？      → ① 設定（本層）
Q2 改變時是因為「外部世界變了」？              → ④ 快取（cache/externals.md）
   （網站改版、法規更新、店家倒了）
Q3 能用程式對檔案／JSON 做出是非判定，
   且不需要外部真值？                          → ③ 機制（hook）
Q4 其餘                                        → ② 規範（SKILL.md / references）
```

🔴 **最常用的那條：句子裡有數字，數字屬於①，句子本身屬於②。**

例：
```
②「步行時間一律實算，不得目測」          ← 判準，不變
①  speed_m_per_min: 70                   ← 參數，隨人變
```

---

## 兩個設定檔

```
config/user-profile.md        跨行程、跟人走（旅伴能力、偏好）
state/<行程名>.md             單趟、短命（硬約束、已排除、交付物）
```

單趟檔用 `繼承：user-profile` 宣告繼承，**只寫與 profile 不同的部分**。
禁止整檔複製（複製會連上一趟的已訂飯店、已付款票券一起繼承，
而那些欄位「有值」會讓檢查通過，比空白更危險）。

---

## user-profile 的欄位

### A. 旅伴表（一人一列，這是解多人衝突的前提）

| 欄位 | 值域 | 用途 |
|---|---|---|
| `id` | `self` / `spouse` / `parent-f` / `child-1` | 所有條件的歸屬鍵 |
| `稱呼` | 本人／太太／媽 | 輸出用，**不用真名** |
| `年齡帶` | 嬰(0-2)／幼(3-6)／童(7-12)／成人／高齡(65+) | 參數選擇依據 |
| `需照顧者` | 否／是(指定 id) | 排隊分流、走失風險的人力計算 |

🔴 **沒有旅伴表就不能排行程。** Gate-H 的過濾項全部從這張表推導。

### B. 移動能力（每位旅伴各一組）

| 欄位 | 單位 | 說明 |
|---|---|---|
| `speed_m_per_min` | m/分 | **必填，無預設值**。不得沿用他人的值 |
| `detour_factor` | 倍 | 繞路係數。市區建物密集取上限 |
| `max_leg_m` | m | 單段上限，超過即須提替代交通 |
| `max_daily_m` | m | **當日總量上限**（原規則只有單段，這是新增） |
| `max_continuous_min` | 分 | 連續活動上限 → 休息間隔 |
| `rest_min` | 分 | 每次休息需時 |
| `需坐著休息` | 是／否 | 「是」＝長椅不算，必須有座位的室內點 |
| `階梯` | 可／吃力／不可 | |
| `陡坡` | 可／吃力／不可 | |
| `久站` | 可／吃力／不可 | |
| `需電梯／無障礙` | 是／否 | 推車、輪椅、膝關節共用 |
| `推車／輪椅` | 無／嬰兒車(可折)／嬰兒車(不可折)／輪椅 | |

### C. 生理節奏（原規則完全沒有這類）

| 欄位 | 範例 |
|---|---|
| `午睡時段` | 無／13:00-14:30 |
| `固定用餐時間` | 無／早07:00 午11:30 晚17:30 |
| `用餐時長` | 分鐘（幼兒與長輩較長） |
| `起床／就寢` | 時間（決定行程起訖） |
| `廁所頻率` | 每 N 分鐘 |
| `尿布台需求` | 是／否（**≠ 廁所**） |
| `哺乳／泡奶需求` | 是／否（需熱水、需哺乳室） |

### D. 飲食（取代規範層的無條件禁令）

| 欄位 | 值域 |
|---|---|
| `禁忌項` | 生蛋／生肉／生魚／半熟／未殺菌乳／生火腿／即食肉／高汞魚／酒精／生菜 |
| `禁忌原因` | 孕期／醫療／宗教／過敏／年齡 |
| `禁忌強度` | **絕對禁**（醫療安全）／**建議避**（舒適度） |
| `攝取上限` | 如：高汞魚 ≤80 g/週 |
| `偏好（正向）` | 想吃的品類 —— **Gate-H 不得把這些過濾掉** |
| `過敏原` | 清單（比孕期禁忌更致命，原規則零規則） |
| `質地需求` | 無／軟食／易咀嚼／兒童餐 |

🔴 **`禁忌強度` 必須區分。** 「絕對禁」與「建議避」混在同一級時，
多人衝突會變成「為了小孩午睡而放寬孕婦步行上限」——拿舒適度換醫療風險。

🔴 **`偏好（正向）` 是防靜默誤殺的唯一機制。** 沒有這欄，
帶爸媽去日本時所有生食店會在過濾階段被殺光，而你只會看到
「過濾後僅 N 家」，不知道壽司店在你看到之前就沒了。

### E. 用餐環境

| 欄位 | 值域 |
|---|---|
| `座位型態 不可` | 榻榻米／座敷／需脫鞋／掘りごたつ／吧台高腳椅／立ち飲み |
| `座位型態 偏好` | 同上的正向版（長輩可能**偏好**座敷） |
| `吸菸店` | 不可／可 |
| `兒童椅` | 需／不需 |
| `推車可進店` | 需／不需／可寄放即可 |
| `噪音耐受` | 高／低（幼兒與長輩需求相反） |

### F. 醫療（去識別化）

| 欄位 | 值域 |
|---|---|
| `風險標籤` | `避免久站`／`避免生食`／`避免高溫`／`需定時服藥` —— **不寫具名診斷** |
| `定時服藥時段` | 時間清單（影響行程排點） |
| `用藥禁用成分` | NSAIDs／偽麻黃素／抗組織胺／咖啡因／含麻黃 |
| `年齡用藥下限適用` | 是／否（幼兒藥妝多標 7 歲以上） |
| `就醫偏好` | 需中文／英文可／保險類型 |

🔴 **用「風險標籤」不用診斷名。** 理由見 `config/隱私.md`。

### G. 訂位用個資

| 欄位 | 說明 |
|---|---|
| `訂位代表人 id` | 指向 A 的 id |
| `姓名（羅馬字）`／`姓名（片假名）`／`電話`／`email` | **建議不存在本檔** |
| `儲存位置` | 預設「向使用者取」，不落檔 |

### H. 查核門檻（原本散在規範層的數字）

本段定義欄位名與用途。**所有值在 `user-profile.md` 的 H 段。**

| 欄位 | 用途 | 原本寫死在哪（節名，不用行號） |
|---|---|---|
| `評分下限` / `樣本數下限` | 餐廳篩選線 | `01-行前規劃.md` 三、餐廳推薦 → 3-3 搜尋範圍宣告 |
| `衝突門檻`（四個量各一） | 判資料衝突 | `SKILL.md` 資料衝突 |
| `折返門檻_分` | 判是否折返 | `01-行前規劃.md` 二、動線與方位 → 2-1 |
| `Gate-O 觸發門檻` | 判要不要跑 Gate-O | 新增（原本是「園區級」循環定義） |
| `日落緩衝_分` | 戶外行程須早於日落前幾分結束 | `01-行前規劃.md` 2-1b 日落稽核 |

⚠️ **引用一律用節名，不用行號。** 行號每次編輯都位移，
而斷鏈的指路比沒有指路更糟（會讓人以為查過了）。

🔴 **本檔是格式定義，不是數值來源。** 看到本檔出現具體數值就是分層錯置，
請搬進 `user-profile.md`。

### Gate-O 觸發門檻的設計note

規範層只能說「園區級」，那是循環定義，所以判準放設定層。

四條判準（面積／跨棟／入口／官方標示接駁）之外**另有一條例外**：
地下街與車站複合體一律直接判要跑，不套四條 ——
那類空間的「面積」與「幾棟」本質上算不清，用四條判會靠 proxy 僥倖命中。
詳見 `user-profile.md` 的 H 段。

🔴 **衝突門檻不可用單一百分比。** 原規則「>30% 視為衝突」在 1–5 分制上是類別錯誤：
tabelog 3.4 vs Google 3.9 差 14.7%，低於 30% 判「無衝突」，
但這 14.7% 橫跨了 3.5 分的篩選線（一邊該排除、一邊該推薦）。

**改為依量別各設一個絕對門檻**（評分／時間／價格／席數各一個）。
**值在 `user-profile.md` 的 H 段 —— 本檔只定義欄位，不放值。**

**且任何跨越決策線的分歧一律回報，不論幅度。**

### I. 第三方來源（各地區的實例）

| 欄位 | 日本 | 澳洲 | 台灣 |
|---|---|---|---|
| `主評分站` | tabelog | Google Reviews + TripAdvisor | Google Reviews |
| `第二來源` | Google Maps | Broadsheet（編輯評比） | PTT／Dcard |
| `商品評價站` | 楽天／Amazon.co.jp | 當地對應站 | momo／PChome |
| `地圖介面語言` | `hl=ja` | `hl=en` | `hl=zh-TW` |

🔴 **規範層只能說「該地區主流評分站（獨立於地圖平台的第二來源）」**，
不得寫 tabelog。tabelog 只有日本有。

### J. 地區規則

| 欄位 | 說明 |
|---|---|
| `出發國` / `目的地國` | 檢疫要**雙向**查（原規則只查「帶回來」） |
| `幣別` | ¥ / A$ / NT$ |
| `稅制顯示` | 税込/税抜 並存（日）／法定含稅（澳）|
| `退稅機制` | 店內或百貨櫃台（日）／離境機場 TRS（澳）|
| `語言處理` | 字形不可讀→行內解釋／字可讀但語意不明→本地慣用語解釋 |

🔴 **退稅機制的差異會改變它屬於哪個階段。** 日本在商品判讀階段，
澳洲 TRS 在離境動線階段（影響留發票、託運、機場預留時間）。

### K. 情境旗標

| 欄位 | 值域 | 用途 |
|---|---|---|
| `行程型態` | 家庭旅遊／出差順遊／獨旅／蜜月 | |
| `效率 vs 舒適` | 1–5 | 獨旅＝效率最大化的唯一入口 |
| `適用條款` | 自動由 B–F 推導 | **每次輸出必須宣告套用了誰的條件** |

🔴 **`適用條款` 是把靜默錯誤變成可觀測的唯一機制。**
沒有它，換人用時我會套用上一個人的參數而沒人會發現。

## 多人衝突的裁決欄位

| 欄位 | 說明 |
|---|---|
| `已裁決衝突` | 衝突項／涉及哪兩個 id／使用者的裁決／日期 |
| `未裁決衝突` | 衝突項／涉及 id —— **必須停下問，不得自行選邊** |
| `本次優先主體` | 使用者明確指定；未指定則不得假設 |

## 缺欄位時怎麼辦

```
必填欄位沒填 → 回報「<某人> 的 <某欄> 未填，無法過濾」
             → 不得空跑、不得沿用他人的值、不得用【隱含的】預設值蒙混
             → 唯一例外：欄位明寫 📝預設 <值> <來源>（見 user-profile 開頭「值的三種狀態」）
               可用它過濾，但輸出必揭露「此欄是預設值，未經本人確認」
```

「蒙混」與「📝預設」的差別：前者是程式裡藏一個常數、沒人知道；
後者是設定檔裡看得見的值、帶來源、每次用都講。

🔴 **`speed_m_per_min` 無預設值是刻意的。** 原規則把 70（孕婦值）
寫成無條件常數，於是帶 70 歲長輩時會套用孕婦速度（偏樂觀，更危險）。
