## 第 11 類：跨 session 失憶（結構缺陷）

不在上表，因為它不是單次失誤。

```
10-04  使用者問「kansai-trip 站台是哪個 session 做的」 → 追不到
10-07  行前 session 抓到「折返跑」「方位沒確認」
10-15  行前 session 結束
10-27  主 session 完全不知道行前 session 存在
       → 交付物沒更新（不知道有線上專案）
       → 方位教訓沒帶過來，大阪城又犯
       → 「講不出日文」10-25 講過，後面又叫他打電話
```

同一件事使用者講了三次。**解法不在規則裡，在 `state/` 的狀態檔機制。**

這是本 skill 的 `state/` 目錄存在的唯一理由：規則文件解決「不知道該怎麼做」，
狀態檔解決「不知道這件事已經講過了」。

## 本規則集的覆蓋率限制

必須向使用者明說，不可宣稱完整：

- 掃描範圍限定 `C:\Users\User\.claude\projects`，**未做全碟掃描**。
- 136 則是「被 NEG／CATS regex 命中的使用者訊息」，**不等於全部失誤**。
  沒被罵但其實也錯的不會進來。
- 掃描本身已被證明有盲區一次：日期切點設 10-17，切掉了 mtime 10-15 的
  行前 session；自設 `strong>=3` 門檻卻當全量回報。
  修正方式是改用完全不同判準重掃（原始全檔文字、不解析訊息、不設日期切點），
  抓出 4 個漏掉的檔案。
- 因此覆蓋率是**下限，不是上限**。

## 「規則寫了」≠「會遵守」

規則文件沒有強制力。真正讓它生效的是三件事：

```
1. SKILL.md 的 description 觸發詞 —— 決定它會不會被載入
2. 狀態檔的「每 session 開頭必讀」—— 決定跨 session 記憶會不會斷
3. 各階段檢核表 —— 決定送出前有沒有真的逐項對過
```

第 3 項最弱（靠自律）。若日後發現仍在重犯，考慮把檢核表做成 hook 強制執行。
