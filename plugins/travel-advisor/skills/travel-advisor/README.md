# travel-advisor — 給使用者看的說明

這份不會被 Claude 載入（Claude 讀的是 `SKILL.md`）。寫給你查閱怎麼用、改哪裡。

## 它是什麼

把 2026 關西行的 136 則糾正編碼成的旅遊顧問 skill。安裝在 user 層，
**所有專案都能用**，不綁 `ppt` 目錄。

## 兩種用法

### 主對話直接載 skill（現場即時用這個）

自動：說「排行程」「推薦餐廳」「怎麼走」「買哪個」等。
手動：`/travel-advisor`

適合：你人在當地問路、臨時換店、看照片判讀商品 —— 要秒回，不能多一層延遲。

### agent 帶 skill（行前規劃、批量查核用這個）

定義檔：plugin 內 `agents/travel-advisor.md`（裝了 plugin 即自動載入；叫用名 `travel-advisor:travel-advisor`）

```yaml
skills:
  - travel-advisor      # 啟動時把 skill 全文注入 agent 的 context
```

適合：排整天行程、逐家查核 10 家以上店家、產交付檔。

**比主對話強在兩點：**

1. **預載不靠判斷。** `skills:` 欄位在 agent 啟動時就注入規則，
   不需要它自己想起來要載。主對話是我判斷「這題要不要載」，判斷錯就沒載 ——
   F 類 41 次（孕期條件）就是這樣犯的。
2. **兩 phase 強制自審。** 定義檔內建 Phase 2，要求重讀十類失誤統計反查，
   並輸出**證據表**（每個主張要附來源 URL），不是打勾清單。
   沒有 URL 的那一列 = 沒查，這是機械判準，自己騙不過自己。

### 🔴 agent 定義檔的改動需要重啟才生效（實測，與官方文件不符）

```
建檔：放在原本空的 ~/.claude/agents/ → 需重啟 Claude Code 才被偵測
      （watcher 只覆蓋 session 啟動時已有內容的目錄）
編輯：官方文件說熱載入，但 2026-11-01 實測「沒有」——
      改完後連續派兩個 agent，兩個引用的都是舊版內容
      （檔案本身已確認是新的：md5 比對、逐行 dump 都對）
```

**所以：改完 agent 定義檔要重啟 Claude Code，再派 agent 驗證。**

驗證方法：派一個 agent 問它「你定義檔的第 N 行寫什麼」，逐字引用。
不要用檔案檢查代替 —— 檔案對不代表 agent 載入的是它。

### 因應設計：關鍵規則一律放 skill，不放 agent 定義檔

因為 agent 定義檔隨時可能是舊版，**防錯規則的真身必須在 skill**
（熱載入可靠）。agent 定義檔只放流程骨架（兩 phase、輸出格式）。

`SKILL.md` 有一節「給透過 agent 載入本 skill 的情況」，內容包括：
- 規則優先序：**skill > agent 定義檔**，矛盾時照 skill 並指出矛盾
- 已知的舊版 agent 定義檔錯誤對照表（place_id 範例等）
- Phase 2 的輸出前提：`references/` 要先 Read 才能寫十類反查與檢核表

**效果：即使 agent 載入的是舊版定義檔，skill 的新規則仍會糾正它。**
重啟只是讓定義檔本身也同步，不是正確性的必要條件。

（CC 2.1.316。skill 的改動則**確認會熱載入**，主對話重新 `/travel-advisor`
就是最新版，實測通過。）

## 四層架構（2026-11-01 重構）

```
① 設定   config/user-profile.md      旅伴能力、門檻、地區實例 —— 換人換國改這裡
         state/<行程名>.md           硬約束、已排除、本趟覆寫
② 規範   SKILL.md + references/      判準與公式，**不含任何數值**
③ 機制   hook                        尚未建置（見下方「為什麼先不做 hook」）
④ 快取   cache/externals.md          會過期的外部事實，每條帶 TTL
```

**判準一句話：句子裡有數字，數字進①，句子進②。**

為什麼要第④層：Gate-V 的機械判準建在 Google 的 CSS class name 上。
放進「不變的規範」層，等於把三個月後必然失效的東西刻進「不變」那層。

### 分層載入（控 token）

```

```

## 核心機制：四道閘門

| 閘門 | 做什麼 | 治哪個病 |
|---|---|---|
| **Gate-O 選項盤點** | **對候選集做加法** —— 逐欄填進入方式/內部移動/設施/時間耦合/當日累積/雨天備案 | 結構缺項（遊園車那類，十類表抓不到） |
| Gate-H 硬約束過濾 | 用**設定檔**的旅伴條件過濾候選，每人各算取最嚴 | F 類 41 次 |
| Gate-V 查證完備 | 全稱規則：任何數字都要來源；第三方=不同營運主體 | A 10 + D 28 + B 7 |
| Gate-S 範圍宣告 | 宣告掃了多少、過濾掉多少、依哪條禁忌排除幾家 | C 10 + J 16 |

🔴 **Gate-O 是新增的，而且性質與其他三道相反。**
前三道都是對已有候選做減法或驗證 —— 所以結構上不可能發現
「該想到的選項沒想到」。136 則糾正全是「我說錯了什麼」，
一個從未被說出的選項在語料裡訊號為零。

優先順序：**1a 醫療風險 > 1b 體力舒適 >** 硬約束 > 查證 > 範圍 > 品質 > 簡潔。
1a/1b 必須分開，否則多人衝突會變成「為了小孩午睡放寬孕婦步行上限」。

## 即時 vs 準確的分級

「100% 第三方背書」與「現場 3 秒回答」互斥，所以依**主張性質**分級：

```
即答        設定檔已有的（硬條件、已排除、已訂位、已算過的動線）→ 讀即答區
即答+標記   方向、大致距離 → 給答案並明標「未重查」
必須等      能不能吃、營業中否、樓層走法 → 完整 Gate-V 後才答
```

判準：**答錯會不會害到人**（醫療風險／花錢／不可逆動作）→ 會就必須等。

狀態檔第 0 節「即答區」行前填好，現場只是讀出來 —— 這樣秒回不必犧牲查證。

## 狀態檔（跨 session 記憶）

```
state/2026-關西.md          本趟實例，已填齊（含踩坑庫、未解懸案、重犯清單）
scripts/init-state.py      新行程建檔：python -I scripts/init-state.py 2027-東京
scripts/check-cache.py     查 cache/externals.md 有沒有過期項（exit 0 全效／3 有過期）
scripts/now.py             現在幾點／日落幾點／戶外收工時刻
scripts/verify-sun.py      對第三方驗 now.py 的日落公式（exit 0 全過／3 有超標／2 缺時區庫）
scripts/live-loc.py        即時位置分享連結 → 此刻座標（exit 0 有／3 分享結束或 >10 分未更新／2 網路／1 不是即時連結）
                           Remote Control 不帶 GPS；使用者開一次即時分享，之後每次問路我自己拉，這是現場首選
                           多人：--who 太太 <連結> --who 爸 <連結>  → 每人一行＋兩兩直線距離；標籤與連結都不落檔
scripts/parse-loc.py       一次性「分享你的位置」連結 → 座標（exit 0 位置／4 地點／3 無座標／2 短網址展不開／1 無連結）
                           遇到即時分享連結會自動轉給 live-loc.py
scripts/verify-gatev.js    實際開 Google Maps 驗 Gate-V 的七項判準還活著沒
                           node scripts/verify-gatev.js            驗 ja + en
                           node scripts/verify-gatev.js --suite ja  只驗日文
                           （exit 0 判準有效／3 有判準失效／1 無法驗證）
                           🔴 check-cache.py 只算日期，答不出「判準還有效嗎」
                           🔴 換地區：在 SUITES 加一組再跑 --suite <新組>，
                              不要改既有的組
```

這是唯一能解「同一件事講三次」的機制。SKILL.md 第一條就是「讀設定」。

下趟開案時照 `state/<行程名>.md` 第 9 節的 SOP 走。

🔴 **不要複製舊狀態檔。** 跑 `init-state.py` 建新的。
複製會把已訂飯店、已付款票券一起帶過來，而那些欄位「有值」會讓檢查通過，
比空白更危險。旅伴條件在 `config/user-profile.md`（跟人走），本來就不必複製。

## 為什麼第③層（hook）先不做

紅藍對抗把十類失誤逐類判了 hook 可行性：

```
可 hook    H 18 + J 16 + C 10 + I 7 + G 5 = 56 次（41%）—— 全是體驗問題
不可 hook  F 41 + D 28 + E 24 = 93 次（68%）—— 全是「錯一次毀整天」的
```

三個不可行的理由（都有依據）：

```
F 類  病發在「我挑候選那一刻」—— hook 所有事件都掛在工具/回合邊界，
      沒有一個掛在那個時機。且判「這家適不適合孕婦」所需資料
      （座席通路/禁菸/時長/能否離席/電梯）不在任何 hook 輸入裡
D 類  要判「3.3 分是不是真的」需要外部真值
E 類  LUCUA B2→阪急本店 的正解「至今未解」—— 沒有真值可比
```

🔴 **最危險的不是做白工，是做完之後的錯覺**：
hook 通過驗證 → 以為「現在有機制強制了」→ README 的「已知弱點」被當成已解決
→ F 類繼續犯，但這次是在一個「每回合都通過閘」的系統裡犯，更晚才發現。

**hook 真正該做的位置**（判不了「判斷對不對」，判得了「有沒有判斷就交出去」）：

```
P0  步行時間腳本 + 「跑了沒貼」閘   唯一能機制化 E 類的路徑
P1  交付物同步閘                   治 H 類 18 次，純檔案事實，零誤擋風險
P2  證據表形狀閘                   檢有無空白 URL 欄、有無「未查」
P3  寫回閘                         說「已寫回」但本回合沒寫 state → 擋
P4  禁句閘                         誤擋風險最高，現場模式預設關
```

做 hook 要改 `~/.claude/settings.json`，所以等使用者點頭。

## 已知弱點

- **主對話的檢核表靠自律**。三個階段各有檢核表，主對話沒有強制機制。
  **走 agent 路徑時這點已補上**（Phase 2 的證據表要求附 URL，是機械判準）。
  若主對話仍在重犯，考慮做成 hook。
- **施作與驗證同一個 agent** —— 你 CLAUDE.md 警告過「驗證器對施作器盲區同構」。
  用兩個機制擋：① Phase 2 強制換判準（讀十類失誤統計反查，不是「我照規則做了嗎」）
  ② 輸出證據表而非打勾。實測有效：2026-10-31 的驗證任務中，agent 自己攔下一個
  D 類錯誤（把自行拼湊的 place_id 當查到的用），並拒絕為沒讀過的 13 項檢核表寫 pass。
- **覆蓋率是下限**。136 則是 regex 命中的，沒被罵但其實也錯的不在內；
  我自己的掃描已被證明有盲區一次。
- **線上站台已完全刪除**（2026-11-01，使用者本人授權後執行）。
  兩階段：① `vercel remove` 移除 5 個 deployment（可逆）
  ② `vercel project rm` 刪除 kansai-trip-map 與 kansai-site 兩個專案（不可逆）。
  驗證：`vercel project ls` 只剩 winbond 兩個、兩個 URL 皆 HTTP 404。
  原始碼仍在 `ppt\kansai-site\public\index.html`。
  若日後重新部署，**務必換掉密碼 `osaka`**（它已出現在多個 session 對話記錄中）。
